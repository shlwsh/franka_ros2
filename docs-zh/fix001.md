# 修复记录: Franka (FR3) RViz 轨迹规划失败 (fix001)

## 1. 问题现象
在 ROS 2 (Jazzy) 环境下运行 Franka (FR3) 机械臂的 MoveIt 仿真测试时，在 RViz 中拖动机械臂末端并点击 `Plan` 按钮后，规划无效，界面显示 `Failed`。

在后台终端或 `rqt_console` 日志中观察到以下核心错误信息：
> **Severity: Error**
> **No acceleration limit was defined for joint fr3_joint1! You have to define acceleration limits in the URDF or joint_limits.yaml**

同时，日志上半部分伴随有大量警告信息：
> **Overrun detected! The controller manager missed its desired rate of 1000 Hz...**

## 2. 问题诊断 (原因分析)

### 2.1 Plan 失败的根本原因
MoveIt 处理 `Plan` 请求时分为两步：
1. **路径规划 (Path Planning)：** 寻找避免碰撞的 3D 几何路径，此步骤实际已成功。
2. **轨迹生成 (Trajectory Generation)：** 为规划出的路径添加时间戳。MoveIt 需调用时间参数化算法（即 `AddTimeOptimalParameterization` 插件）。

该算法严格依赖机器人的**最大加速度极限**数据。经排查，系统环境中的 `franka_fr3_moveit_config` 包不仅未包含 MoveIt 所需格式的 `joint_limits.yaml` 文件，且其 `moveit.launch.py` 启动文件也没有加载包含加速度限制的 `robot_description_planning` 参数。
因为读取不到任何加速度数据，参数化插件报错崩溃，直接导致整个 `Plan` 过程失败。

### 2.2 Overrun 警告的原因
法兰卡机械臂的底层硬件控制需要 1000Hz（即 1毫秒）的控制循环。由于当前计算资源或非实时操作系统的调度延迟（单次循环可能耗时 2~4ms），导致达不到所需的 1000Hz 通信频率而产生警告。
虽然这与 `Plan` 失败无关，但在真实物理设备上点击 `Execute` 执行时，可能引发机器人抖动甚至触发安全机制导致急停。

## 3. 修复方法与步骤

为了解决无法规划的问题，采取了以下修复措施：

**步骤 1：补全关节限制配置文件**
在工作空间的 `franka_fr3_moveit_config/config/` 目录下创建了 `joint_limits.yaml` 文件，为机械臂的所有七个关节（`fr3_joint1` 至 `fr3_joint7`）设定了速度和加速度阈值。
**关键配置**：必须包含 `has_acceleration_limits: true` 并赋予 `max_acceleration` 合理的数值。
```yaml
joint_limits:
  fr3_joint1:
    has_velocity_limits: true
    max_velocity: 2.62
    has_acceleration_limits: true
    max_acceleration: 3.75
  # ... (对 fr3_joint2 ~ fr3_joint7 应用类似配置)
```

**步骤 2：在 Launch 文件中加载配置**
修改 `franka_fr3_moveit_config/launch/moveit.launch.py` 文件，通过 `load_yaml` 函数读取新创建的 `joint_limits.yaml`，将其包装为 `robot_description_planning` 字典，并作为参数传入给 `move_group` 节点：
```python
    joint_limits_yaml = load_yaml(
        'franka_fr3_moveit_config', 'config/joint_limits.yaml'
    )
    robot_description_planning = {'robot_description_planning': joint_limits_yaml}

    # 在 move_group Node 的 parameters 列表中添加:
    # robot_description_planning,
```

**步骤 3：重新编译并应用**
完成修改后，在工作空间根目录下执行局部编译更新包：
```bash
colcon build --packages-select franka_fr3_moveit_config
```
重启对应的 ROS 2 启动脚本（如 `./scripts/start.sh`），此时由于 MoveIt 已获取完整的加速度参数，时间参数化算法能够正常执行，RViz 中的 `Plan` 功能恢复正常。

## 4. 结论与建议
* **结论**：RViz 规划失败卡在时间参数化阶段，通过补充 `joint_limits.yaml` 和更新 Launch 参数加载逻辑，已成功修复问题。
* **对于 Overrun 警告的建议**：在目前仿真验证阶段（`use_fake_hardware:=true`）可直接忽略。但在未来如果需要控制真实的物理机械臂，强烈建议在物理机上安装 **Real-Time (实时) 内核** 的 Ubuntu 系统，以确保底层 1000Hz 的稳定控制。

## 5. 附录：rqt_console 工具使用指南

在本次排查中，通过日志分析精准定位了问题。ROS 2 提供了 `rqt_console` 这一强大的图形化日志查看工具，非常适合用于过滤、搜索和分析节点输出的日志。

### 5.1 安装步骤
如果在系统中尚未安装该工具（表现为找不到命令），可以通过 `apt` 进行安装。
在终端执行以下命令：
```bash
sudo apt update
sudo apt install ros-jazzy-rqt-console
```
*(注意：请不要使用 ROS 1 的 `rosrun` 或安装 `rosbash`，在 ROS 2 环境中直接安装对应的 jazzy 插件即可)*

### 5.2 启动方法
确保当前终端已经加载了 ROS 2 环境（如 `source /opt/ros/jazzy/setup.bash`），然后运行以下命令即可打开图形化界面：
```bash
ros2 run rqt_console rqt_console
```

### 5.3 核心功能与使用技巧
1. **等级过滤 (Severity Filter)：**
   可以勾选或取消勾选 `Debug`, `Info`, `Warn`, `Error`, `Fatal`，快速屏蔽无关的普通信息，只关注 `Error` 或 `Warn`（本次排查就是通过提取 Error 日志找到了根本原因）。
2. **文本与节点过滤 (Message / Node Filter)：**
   在排查特定问题时，可以在过滤框输入关键字（如 `fr3_joint1`）或节点名（如 `move_group`），界面会实时过滤出相关的日志行。
   *示例：你可以排除掉 `controller_manager` 刷屏的 Overrun 警告，聚焦于 MoveIt 的报错。*
3. **暂停与清除：**
   当日志滚动过快时，点击界面上方的 **Pause** (暂停按钮) 可固定画面以便仔细阅读；分析完毕后，可点击 **Clear** (扫帚图标) 清空面板，重新记录新一次操作的日志。
