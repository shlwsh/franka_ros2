基于 [多智能体协作论文生产系统设计.md](./多智能体协作论文生产系统设计.md) 和 [Paper-I多智能体迭代完善方案.md](./Paper-I多智能体迭代完善方案.md)，在现有 Agent Platform 技术栈上实现 Paper Forge 模块。

- 导航: Activity Bar + Global Sidebar (Teleport 插槽模式) — [AppNav.vue](file:///home/ros/work/winning-deepagents/src-frontend/src/components/AppNav.vue)

- Agent: `createDeepAgent` + `CompiledSubAgent` — [hierarchical-agent.ts](file:///home/ros/work/winning-deepagents/examples/hierarchical/hierarchical-agent.ts)
- 持久化: PostgreSQL (agentdb) — 已有 SessionStore 和 Checkpointer
- 论文初稿: LaTeX 格式 — `/home/ros/work/paper1/doctor/paper1/latex/`

## User Review Required

> [!IMPORTANT]
> **论文目录访问**: Paper Forge 需要读写 `/home/ros/work/paper1/doctor/paper1/` 目录下的 LaTeX 文件。实现时通过 API 参数传入论文根目录路径，不硬编码。

> [!WARNING]
> **LLM 调用成本**: 多智能体评审循环中，每轮评审会调用 7 个 Agent（PI + Student + Statistician + Editor + Reviewer×2 + Ethics），每个 Agent 都需要读取全文。建议初期使用 `deepseek-v3`（DashScope 配置）控制成本，后续可切换更强模型。

> [!IMPORTANT]
> **模块范围确认**: 本次实现采用**渐进式方案**，优先实现核心可用的最小闭环（评审→修改→再评审），而非完整的 7 阶段流水线。这样能最快交付可用功能，后续再扩展。

## Open Questions

1. **评审轮次上限**: 默认设置 3 轮，是否合适？
2. **论文语言**: Paper I 是英文论文，Agent 的审稿意见是用中文还是英文输出？建议：审稿意见用中文（方便理解），修改后的 LaTeX 保持英文。
3. **是否需要自动编译 LaTeX**: 需要系统中安装 `latexmk` + `texlive`。如果 WSL 中未安装，可先跳过自动编译功能。

## Proposed Changes

### 后端: Paper Forge API

#### [NEW] [paper-forge.ts](file:///home/ros/work/winning-deepagents/services/agent-platform/src/routes/paper-forge.ts)

Paper Forge 专用 Hono 路由，提供以下 API:

```
POST /api/paper-forge/projects          — 创建论文项目 (传入论文目录路径)
GET  /api/paper-forge/projects          — 列出所有项目
GET  /api/paper-forge/projects/:id      — 获取项目状态
POST /api/paper-forge/projects/:id/review — 触发一轮多智能体评审
GET  /api/paper-forge/projects/:id/reviews — 获取评审历史
POST /api/paper-forge/projects/:id/revise — 基于评审意见执行修改
POST /api/paper-forge/projects/:id/stream — SSE 流式执行 (评审/修改过程实时输出)
GET  /api/paper-forge/projects/:id/files — 列出论文文件树
GET  /api/paper-forge/projects/:id/files/:path — 读取指定文件内容
```

#### [NEW] [paper-forge/](file:///home/ros/work/winning-deepagents/services/agent-platform/src/paper-forge/)

Paper Forge 核心模块目录:

```
src/paper-forge/
├── index.ts              # 模块导出
├── orchestrator.ts       # 编排器: 管理评审/修改循环
├── agents.ts             # 7 个角色 Agent 的创建工厂
├── tools.ts              # 论文专用工具 (读写 LaTeX、验证引用等)
├── types.ts              # 类型定义 (项目、评审报告、阶段等)
└── store.ts              # 项目状态持久化 (PostgreSQL)
```

**关键设计**:
- `orchestrator.ts`: 使用 `createDeepAgent` 创建顶层编排 Agent，将 7 个角色 Agent 注册为 `CompiledSubAgent`
- `agents.ts`: 每个角色 Agent 用 `createDeepAgent` 创建，注入角色特定的 system prompt 和论文领域知识
- `tools.ts`: 提供 `read_paper_section`、`edit_paper_section`、`list_paper_files`、`validate_references` 等 LangChain tool
- `store.ts`: 在 PostgreSQL 中创建 `paper_projects` 和 `paper_reviews` 表存储项目和评审数据

### 数据库

#### [NEW] Paper Forge 数据表

在 PostgreSQL (agentdb) 中创建:

```sql
-- 论文项目表
CREATE TABLE IF NOT EXISTS paper_projects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title VARCHAR(500) NOT NULL,
  paper_dir VARCHAR(1000) NOT NULL,     -- 论文目录绝对路径
  current_phase VARCHAR(50) DEFAULT 'precheck',
  review_round INT DEFAULT 0,
  max_review_rounds INT DEFAULT 3,
  status VARCHAR(50) DEFAULT 'active',  -- active/completed/paused
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 评审记录表
CREATE TABLE IF NOT EXISTS paper_reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID REFERENCES paper_projects(id),
  round_number INT NOT NULL,
  reviewer_id VARCHAR(100) NOT NULL,
  decision VARCHAR(50),
  scores JSONB DEFAULT '{}',
  major_issues JSONB DEFAULT '[]',
  minor_issues JSONB DEFAULT '[]',
  strengths JSONB DEFAULT '[]',
  full_report TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);
```
