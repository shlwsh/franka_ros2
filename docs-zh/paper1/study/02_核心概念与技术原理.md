## 1. 云–边–端三层架构

```
┌─────────────────────────────────────────────────────────┐
│  Cloud（云端）                                            │
│  高级视觉模型、EMR 集成（论文 I 中为 stub 占位）              │
│  位置：doctor/paper1                                     │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP（上传清晰帧）
┌──────────────────────────▼──────────────────────────────┐
│  Edge（边侧）                                             │
│  FastAPI 网关 (:8000)                                    │
│  ├── Edge-IQA：给每帧打分 Q_img                           │
│  └── LangGraph：决定 upload / resample / fail_safe       │
│  位置：franka_api_server + doctor/paper1                 │
└──────────────────────────┬──────────────────────────────┘
                           │ DDS / ROS 2
┌──────────────────────────▼──────────────────────────────┐
│  Device（设备层）                                         │
│  FR3 机械臂 + 相机 + MoveIt 运动规划                       │
│  Skills：go_to_tongue_pose / go_to_face_pose             │
│  位置：franka_ros2（franka_hardware, MoveIt）             │
└─────────────────────────────────────────────────────────┘
```

**关键设计原则**：感知和路由**不进** 1 kHz ROS 控制循环，保证实时安全。

## 2. Edge-IQA（边侧图像质量评估）

### 2.1 是什么？

Edge-IQA 是一个**轻量级、可解释、CPU 友好**的图像质量打分器，在边侧网关对每一帧给出 0–1 的质量分数 \(Q_{img}\)。

### 2.2 输入与输出

| 项 | 内容 |
|----|------|
| **输入** | RGB 图像；可选 COCO 舌框 → ROI 裁剪后 resize 512×512 |
| **输出** | `q_img`（0–1 分数）、`flags`（失败标签）、`t_iqa_ms`（耗时） |

> **ShezhenV3 标定（ROI）**：清晰/模糊中位数 **0.516 / 0.414**，τ = **0.465**（n=1144）。

### 2.3 核心公式

设灰度图为 \(I\)，两个特征：

**清晰度 S（Laplacian 方差）**：
\[
S = \mathrm{Var}(\nabla^2 I), \quad \text{归一化到 } [0,1]
\]

**曝光 E（偏好中灰）**：
\[
E = 1 - \frac{|\mathrm{mean}(I) - 0.5|}{0.5}
\]

**融合质量指数**：
\[
Q_{img} = 0.65 \cdot S + 0.35 \cdot E
\]

权重 0.65 / 0.35 表示清晰度比曝光更重要（舌象采集对模糊更敏感）。

### 2.4 失败标签 flags

| 标签 | 触发条件 |
|------|----------|
| `blur` | 清晰度 S < 0.35 |
| `underexposed` | 均值 < 0.25 |
| `overexposed` | 均值 > 0.85 |

### 2.5 阈值 τ 的标定

在验证集上：
- 清晰图像 \(Q_{img}\) 中位数 ≈ **0.819**
- 模糊图像 \(Q_{img}\) 中位数 ≈ **0.191**
- 推荐阈值 τ = **0.505**（二者中点，落在 [0.45, 0.65] 内）

> **τ 的物理含义**：\(Q_{img} \geq \tau\) 认为「足够清晰，可以上传」；\(Q_{img} < \tau\) 认为「需要重拍」。

### 2.6 性能指标

| 指标 | 值 |
|------|-----|
| 复杂度 | \(O(HW)\)，线性于像素数 |
| 离线 p50 | 8.01 ms |
| 离线 p95 | 9.57 ms（@512px，CPU） |
| API 路径（含网关+子进程） | ~27 ms（< 35 ms 门槛） |
| 清晰/模糊分离度 | min(clear) − max(blur) > 0.55 ✅ |

### 2.7 为什么不用通用深度学习 IQA？

- 边侧需要 **< 30 ms** 实时约束（Edge-IQA p95≈9.6 ms）
- 需要 **可解释** 的 blur/exposure 标签（JSONL 可审计）
- 任务目标是**路由门控**（Q ≥ τ），不是 MOS 排名
- B3 基线为 **ShezhenV3 train 上训练的 MobileNetV3-Small**（`learned_b3.py`）；M2/重采率与 B2 对比见全量矩阵；主 claim 仍基于可解释 B2

> 详见 [06_Edge-IQA算法详解与业界对比.md](./06_Edge-IQA算法详解与业界对比.md)

## 3. Confidence-Aware Routing（置信度感知路由）

### 3.1 是什么？

给定 Edge-IQA 分数 \(Q_{img}\) 和当前重拍次数 \(r\)，路由函数决定下一步动作。

### 3.2 路由函数（必须背）

\[
\text{route}(s)=
\begin{cases}
\text{upload\_cloud} & Q_{img}\geq\tau \land r\leq K \\
\text{resample\_edge} & Q_{img}<\tau \land r\leq K \\
\text{fail\_safe} & r>K
\end{cases}
\]

| 决策 | 含义 | 后续动作 |
|------|------|----------|
| `upload_cloud` | 质量合格 | 上传到云端 vision stub |
| `resample_edge` | 质量不合格且还有重拍预算 | 调用 `go_to_tongue_pose` 重拍 |
| `fail_safe` | 重拍次数超限 | 上报云侧人工/默认位，终止 |

**超参数**：
- \(\tau = 0.505\)（标定阈值）
- \(K = 2\)（最大重拍次数）

### 3.3 LangGraph 状态机

```
capture → edge_iqa → route → upload_cloud
                         → resample_edge → (回到 capture)
                         → fail_safe
```

**与 B1 的关键区别**：B1 只做单次判定，不重拍；B2 重拍后会**重新**进入 `edge_iqa`，形成闭环。

### 3.4 为什么用 LangGraph 而不是普通 FSM？

| 对比项 | 普通 FSM | LangGraph |
|--------|----------|-----------|
| 条件边 | 隐式 | 显式、可测试 |
| 日志 | 难导出 | JSONL 轨迹一键导出 |
| 与论文 II | 不统一 | 多 Agent 栈可复用同一框架 |

## 4. 基线 B0–B3（实验对比组）

| 代号 | 描述 | 论文用途 |
|------|------|----------|
| **B0** | 无边缘 IQA；**全部**上传云端再评判 | 主对比（naive baseline） |
| **B1** | 边缘 IQA + 固定 τ；**无** LangGraph（单次判定，不重拍） | 消融「路由/重拍」 |
| **B2** | Edge-IQA + Confidence-Aware Routing | **本文主方法** |
| **B3** | MobileNetV3-Small（train 微调，ROI 224×224） | 可选：学习 IQA，牺牲 flags 换更强 blur 排序 |

### 4.1 如何向导师解释 B2 vs B1？

> B1 的 M1 p50 更低（324 ms vs 364.7 ms），但 M2 有效帧率几乎没提升（0.505 vs 0.495）。  
> 原因：B1 **只过滤不重拍**，无效帧仍然混入；B2 通过边侧重拍换取高有效率（0.988）。  
> **取舍**：B2 用略高的 RTT 换接近 100% 的有效帧率——对医疗采集场景，有效率比纯延迟更重要。

### 4.2 如何向导师解释 B2 vs B0？

> B0 把所有帧（含模糊）都上传云端，M2 只有 49.5%；B2 在边侧过滤+重拍，M2 达 98.8%，同时 M1 p50 从 397.6 ms 降到 364.7 ms（避免无效上传的云端往返）。

| ID | 定义 | 目标（vs B0） | 对应图表 |

### 5.1 RTT 是什么？

**Round-Trip Time（往返时延）**：从采集一帧图像到做出路由决策并完成动作的端到端时间。

主实验 M1 包含**模拟云端往返**；M6 辅轨**不含**云端上传，只测边侧本地回路。

> **陷阱**：M6 的 p50=7.38 ms **不能**与主轨 M1 的 364.7 ms 直接对比——测量范围不同。

## 6. 闭环 JSONL 日志

每 trial 写一行 JSON，10 个必填字段：

```json
{
  "trial_id": 1,
  "image_path": "experiments/synthetic/clear/clear_0000.png",
  "q_img": 0.8075,
  "flags": [],
  "retry_count": 0,
  "route_decision": "upload_cloud",
  "t_capture": "2026-05-29T...",
  "t_iqa": "2026-05-29T...",
  "t_route": "2026-05-29T...",
  "latency_ms": 15.89
}
```

**用途**：Supplementary 可复现样例；M6 辅轨趋势验证；**不是** Table II 主数据来源。
