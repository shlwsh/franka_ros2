## 2. 核心 API 端点

### 2.1 Vision Evaluate（Edge-IQA 网关）

```bash
POST /api/v1/vision/evaluate
Header: X-API-Key: franka-api-default-key
Content-Type: multipart/form-data   # file=@image.png
```

**响应示例**：
```json
{
  "q_img": 0.72,
  "flags": ["blur"],
  "t_iqa_ms": 12.4,
  "threshold_tau": 0.55,
  "meta": { "scorer": "edge_iqa", "mode": "subprocess" }
}
```

**调用链**：
```
routers/vision.py
  └─► services/paper1_iqa.py::evaluate_image_path()
        └─► 子进程：python -m edge_iqa.cli --image <path> --json
              （doctor/paper1/edge_iqa/scorer.py）
```

### 2.2 Skills API（具名位姿）

```bash
POST /api/v1/motion/skills/go_to_tongue_pose
POST /api/v1/motion/skills/go_to_face_pose
```

| Skill | 关节角（7 DOF） |
|-------|----------------|
| `go_to_tongue_pose` | `[0, -0.785, 0, -2.356, 0, 1.571, 0.785]` |
| `go_to_face_pose` | `[0.1, -0.5, 0.05, -2.0, 0, 1.4, 0.7]` |

配置来源：`franka_api_server/skills/poses.yaml`

### 2.3 关节运动 API

```bash
POST /api/v1/motion/move_joints
{
  "goal_joint_configuration": [...],
  "max_velocity_scaling": 0.3,
  "async_execution": true
}
```

## 3. 闭环数据流（一次 trial）

```
1. capture
   └─► 相机/Gazebo → capture_001.png

2. edge_iqa
   └─► POST /api/v1/vision/evaluate
       └─► 返回 { q_img, flags, t_iqa_ms }

3. route（LangGraph 决策）
   └─► q_img >= τ → upload_cloud
       q_img < τ  → resample_edge
       retry > K  → fail_safe

4. resample_edge（如需）
   └─► POST /api/v1/motion/skills/go_to_tongue_pose
       └─► ros_bridge → MoveIt → FR3

5. JSONL 写盘
   └─► 10 字段一行
```

## 6. 三个关键设计决策

### 6.1 为什么 Edge-IQA 不内嵌到 franka_hardware？

- 算法贡献独立于硬件平台
- 离线实验无需启动 ROS
- 同一 `scorer.py` 可在网关和离线实验复用
- **算法边界清晰**：主仓迭代不受 ROS 包构建约束

### 6.2 为什么用 Skills API 而非直接 move_joints？

- 具名 Skill 是跨平台抽象（LangGraph 只需知道「去舌位」）
- `poses.yaml` 可在不改代码的情况下调整位姿
- 符合论文 §3.3 的「采集意图」表达要求

### 6.3 PAPER1_MODE 的作用

`PAPER1_MODE=1` 时禁用：
- `POST /api/v1/controller/stiffness`
- `POST /api/v1/controller/collision`

原因：论文 I **不使用**阻抗/碰撞控制（属博士论文他章），避免误触影响实验。
