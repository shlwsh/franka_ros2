## 2. 核心发现（quick）

### 2.1 B2：路由「网络盲」

在当前仿真中，**B2 的 M2 恒为 0.625**，与 RTT、丢包无关。

原因：B2 仅用 \(Q \geq \tau\) 决策，**不把 RTT / P_loss 纳入路由**；网络只影响 M1（upload 段延迟），不改变 valid 判定。

| 含义 | 说明 |
|------|------|
| 优点 | 简单、可解释 |
| 局限 | 差网络下仍可能 upload，真实场景易失败（待 Phase 2b 建模 upload 失败率） |

### 2.2 B2d：随丢包自适应

**B2d 的 M2 随 \(P_{loss}\) 单调下降**（RTT 网格上平均）：

| \(P_{loss}\) | B2d M2（avg） | B2 M2 |
|-------------|---------------|-------|
| 0.00 | 0.625 | 0.625 |
| 0.05 | 0.600 | 0.625 |
| 0.10 | 0.550 | 0.625 |
| 0.20 | 0.500 | 0.625 |

**M3 重采率**随 loss 上升（B2d 0.40 → 0.525），符合「提高 τ → 更倾向重采」的设计。

### 2.3 RTT 对 M2

固定 τ 与动态 τ 下，**M2 几乎不随 cloud RTT 变化**；M1 p50 随 RTT 线性上升（50 ms 格 ≈ 68 ms 总 RTT，500 ms 格 ≈ 514 ms）。

---

## 3. 论文叙事建议

1. **B2 主 claim 不变**：可解释、低延迟、物理重采闭环。  
2. **B2d 创新点**：网络感知阈值；差网络下**主动保守**（M2↓、M3↑），避免无效 upload。  
3. **诚实表述**：当前 offline 仿真未建模「upload 失败回退」；B2d 的优势体现在**路由策略可随网络调节**，而非 quick 网格上 M2 高于 B2。  
4. **后续 Phase 2b**：为 B2 增加 \(P(\text{upload fail} \mid P_{loss})\)，预期差网络下 B2 有效质量下降、B2d 相对优势更明显。
