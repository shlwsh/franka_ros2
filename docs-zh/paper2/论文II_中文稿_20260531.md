# 论文 II 中文稿

## 基于知识图谱门控的多智能体具身闭环冲突重对齐方法：面向多模态电子病历合成的反幻觉原型研究

**作者**：石洪雷  
**版本**：2026-05-31 MVP 草稿  
**证据来源**：`doctor/paper2/experiments/logs/paper2_run_001.jsonl`、`doctor/paper2/experiments/results/*.csv`  
**重要说明**：本文当前为 synthetic MVP 草稿，不包含真实临床记录、受保护健康信息、外部大模型调用或受限医学本体原始数据。所有结果仅证明项目内闭环原型和实验管线已经跑通，不应被表述为临床有效性结论。

---

## 摘要

多模态电子病历合成需要同时处理非结构化主诉文本、视觉体征、知识图谱证据和结构化互操作标准。当文本症状与视觉标签不一致、图像质量不足或结构化输出缺少关键字段时，线性大模型生成流程容易产生无法追溯的事实幻觉。为此，本文提出一种基于知识图谱门控的多智能体具身闭环冲突重对齐方法。该方法在 `franka_ros2` 项目的边缘 API 和具身 Skills 基础上，构建 Symptom Agent、Vision Agent、KG Conflict Agent、Action Agent 与 EMR/FHIR Agent 组成的状态图。系统以统一 Context Object 传递症状实体、视觉标签、KG 匹配、冲突置信度、工具调用和 FHIR 草稿；当门控分数低于阈值时，状态机触发补拍、补问、知识图谱查询或 FHIR 修复，而不是直接生成终态病历。

在当前 MVP 中，我们构造 24 个 synthetic trial，并在 B0 线性生成、B1 自反思、B2 KG 门控、B3 具身闭环、B4 工具增强闭环五个基线下运行，共生成 120 行 JSONL 审计轨迹。实验结果显示，B0 的冲突检出 F1 为 0.7500，幻觉率为 0.6250；引入 KG 门控后，B2 的冲突检出 F1 达到 1.0000，幻觉率降至 0.0000；工具增强闭环 B4 在保持冲突检出 F1 为 1.0000 的同时，将 FHIR 有效率提升至 0.6250。本文还新增数据集注册表、CSV/JSONL 病例加载器、no-PHI 样例数据重放脚本和可训练 graph-attention-lite 图基线，为后续受控数据和真实 GNN/GAT 接入提供工程接口，但不声称已经完成真实公开数据集实验或大规模图神经网络训练。结果说明，该原型已经跑通“文本/视觉感知 -> KG 冲突门控 -> 工具调用 -> 结构化输出校验”的可追溯研究链路，为后续接入真实公开数据集、标准 FHIR 验证器和 GNN 图嵌入提供了工程底座。

**关键词**：多智能体系统；知识图谱；反幻觉；电子病历；HL7 FHIR；具身智能；ROS 2；Franka FR3

## 1. 引言

数字化诊疗与具身医疗采集系统正在把图像、语音、文本和机器人状态汇入统一的临床信息流。与单模态记录相比，多模态电子病历合成更容易暴露三个问题。第一，主诉文本和视觉体征可能发生语义冲突。第二，图像质量、遮挡和采集位姿会影响视觉标签可信度。第三，生成式模型可能在缺少证据时补全看似合理但不可追溯的临床断言。

现有 `franka_ros2` 项目已经为论文 I 建立了边缘图像质量评估、置信度路由和 FR3 重采样的闭环。论文 II 在此基础上提出新的科学问题：当冲突不再只是图像质量低，而是跨越文本、视觉、知识图谱和结构化病历标准时，系统能否通过多 Agent 状态机主动阻断幻觉路径，并把工作流重定向到补拍、补问、检索或修复节点？

本文贡献如下：

1. 提出面向多模态 EMR 合成的 KG-gated multi-agent closed-loop 架构，将症状抽取、视觉评分、KG 冲突门控、具身工具调用和 FHIR 校验纳入同一状态对象。
2. 在 `doctor/paper2` 中实现可复现 synthetic MVP，生成 JSONL、CSV 和报告，证明研究管线已经可运行。
3. 给出 B0-B4 五种基线，初步量化 KG 门控和工具调用对冲突检出、幻觉率和 FHIR 有效率的影响。
4. 明确 `franka_ros2` 的工程边界：ROS 2/MoveIt/FastAPI/Skills 作为具身工具层，医学推理和论文主实验位于 `doctor/paper2` 研究层。

## 2. 背景与相关标准

本文原型采用状态图组织多 Agent 工作流。LangGraph 官方文档将 `StateGraph` 用作基于共享状态的图执行抽象，适合表达带条件边的多步骤 Agent 流程。HL7 FHIR 的 Bundle、Composition 与 Observation 资源为结构化临床文档和观察项提供了互操作表达，其中 FHIR R4 文档 Bundle 要求第一项为 Composition。MIMIC-IV、MIMIC-IV-Note 和 MIMIC-CXR 等 PhysioNet 公开受控数据集可作为后续 EHR 文本和影像报告来源，但使用前必须遵守 credentialing、数据使用协议和本地伦理审批要求。SNOMED CT 等本体资源需要关注浏览器和许可证要求，本文 MVP 仅使用自建小型 KG stub，并用 placeholder-only 的实体映射表记录 ICD/SNOMED/FHIR 对齐接口，不分发受限本体原文。

## 3. 方法

### 3.1 总体架构

系统分为三层：

1. **认知研究层**：`doctor/paper2`，包含状态机、Agent、KG stub、实验脚本和论文结果。
2. **边缘 API 层**：`franka_api_server`，提供 `/api/v1/vision/evaluate`、`/api/v1/motion/skills/{skill_name}`、状态查询和 WebSocket。
3. **具身执行层**：`franka_*` ROS 2 包，负责 FR3、MoveIt、Gazebo 和 ros2_control 执行。

### 3.2 统一状态对象

Paper2State 包含 `trial_id`、`case_id`、`symptom_text`、`symptom_entities`、`q_img`、`vision_tags`、`kg_matches`、`gamma_conflict`、`route_decision`、`tool_calls`、`emr_draft`、`fhir_bundle`、`fhir_valid` 和 `latency_ms`。所有 trial 写入 JSONL，使每个论文数字都能回溯到运行轨迹。

### 3.3 知识图谱门控

KG Conflict Agent 使用症状实体、视觉标签和小型 KG stub 计算：

```text
gamma_conflict = 0.28 * entity_completeness
               + 0.24 * vision_quality
               + 0.36 * kg_consistency
               - 0.22 * contradiction_penalty
```

当文本实体缺失、图像质量过低或 KG 中存在矛盾边时，状态机不会直接生成病历，而是进入 `ask_followup`、`resample_vision`、`query_kg` 或 `human_review`。

为推进方案中 P2-2 的图谱实验，本稿同时导出 `doctor/paper2/kg/kg_edges.csv`，实现确定性 signed-edge propagation 消融，并新增 message-passing embedding 与 graph-attention-lite 消融。message-passing embedding 用 KG 节点 one-hot 向量初始化，通过支持边和矛盾边进行有符号消息传递，再用文本实体池化向量与视觉标签池化向量的余弦相似度作为兼容性评分。graph-attention-lite 则从 KG 边和 synthetic replay 标签中学习支持边、矛盾边、低质量图像和实体缺失的注意力权重。该实验仍不是完整大规模 GNN 训练，但已从纯规则 JSON stub 推进到可审计边表、可复现嵌入评分和无外部依赖的可训练图基线。

为推进 P2-KG-2，本稿新增 `doctor/paper2/kg/entity_map.csv` 和 `doctor/paper2/kg/entity_map_coverage.py`。映射表覆盖 KG stub 中的症状和视觉体征实体，记录 project-local code、FHIR target、ICD/SNOMED placeholder 与许可证状态。该表只用于固定字段和覆盖率口径，不包含真实 ICD/SNOMED/UMLS 受限原文；`ONTOLOGY_LICENSE_NOTES.md` 记录后续替换真实标识前的许可证约束。

### 3.4 工具调用与具身补拍

Action Agent 当前实现三类工具：`execute_skill`、`ask_followup` 和 `query_kg`。在 B3/B4 中，视觉低质样本会触发 synthetic `go_to_tongue_pose` 补拍工具，模拟 FR3 调整采集位姿后图像质量提升。未来真机实验只允许调用具名 Skill，不允许研究层直接发送裸关节角。

### 3.5 EMR/FHIR 生成与修复

EMR/FHIR Agent 生成包含 Composition、Patient 和 Observation 的最小 document Bundle，并要求首个 entry 为 Composition，Composition 与 Observation 均具有 Patient subject reference。若 Observation 缺失，B4 可触发 `repair_fhir` 工具补齐并重新校验。当前系统新增了 `doctor/paper2/tools/fhir_validator.py` 适配层：默认使用本地结构校验，同时可通过 `PAPER2_FHIR_VALIDATOR_CMD` 接入外部 FHIR validator CLI，并在 JSONL 中记录验证模式。为形成可复跑证据，`doctor/paper2/experiments/run_fhir_validation_replay.py` 会导出每个 trial 的 Bundle JSON，并对同一批 Bundle 生成批量 validator replay CSV 和报告；`run_official_fhir_validator_audit.py` 则面向官方 validator 复跑，记录命令、artifact SHA-256、外部通过数和 unexpected reject。

为推进 P2-3 的真实边缘工具联调，本文还提供 `doctor/paper2/tools/franka_probe.py`。该 probe 可以检测 `franka_api_server` 的 `/status/joints` 和 `/motion/skills` 是否可用，并返回 `online/partial/offline`，但不会让 synthetic MVP 因 ROS 或 API 离线而失败。

### 3.6 数据集注册与重放桥接

为推进 P2-5 的公开/受控数据主实验，本文新增 `doctor/paper2/datasets/registry.json`、`doctor/paper2/tools/dataset_loader.py` 和 `doctor/paper2/experiments/run_dataset_replay.py`。注册表区分 open、controlled 和 restricted 数据源，记录许可证、访问级别、来源类型和本地派生路径占位。默认跟踪的 `sample_open_csv` 为项目内 no-PHI synthetic fixture；`mimic_iv_note_placeholder` 与 `mimic_cxr_placeholder` 只记录受控数据占位元数据，不包含原始记录、图像或报告。加载器支持 CSV、JSONL 和 JSON，并强制检查 `case_id`、`symptom_text`、`expected_entities`、`vision_tags`、`q_img` 与 `conflict_label` 等字段。受控数据在没有显式 `allow_controlled` 和本地派生文件时会失败，从工程上避免把未授权临床数据误提交进仓库。

## 4. 实验设计

### 4.1 数据与任务

实验使用 8 个 synthetic case 模板扩展为 24 个 trial。每个 case 含主诉文本、期望实体、视觉标签、图像质量分数、冲突标签和 FHIR 缺失标记。冲突类型包括视觉低质、文本实体缺失、文本-视觉矛盾和 FHIR 缺字段。另以 `sample_open_csv` no-PHI fixture 运行数据集重放桥接实验，验证注册表、文件加载、B0-B4 重放和结果导出的完整链路。

### 4.2 基线

| 基线 | 名称 | 描述 |
|---|---|---|
| B0 | Linear EMR | 不做门控，直接生成 EMR/FHIR |
| B1 | Self-Reflection | 基于图像质量和文本完整度做浅层自反思 |
| B2 | KG-Gated | 引入 KG 门控，不执行具身补拍 |
| B3 | Embodied Closed Loop | KG 门控 + 具身补拍工具 |
| B4 | Tool-Enhanced Closed Loop | B3 + FHIR 修复和更严格人工审阅策略 |

### 4.3 指标

主要指标包括冲突检出 Precision/Recall/F1、幻觉率、FHIR 有效率、平均闭环延迟和工具调用率。结果文件为 `doctor/paper2/experiments/results/paper2_summary.csv`。图表由 `doctor/paper2/figures/plot_results.py` 从 CSV 自动生成，避免手工改图导致数字漂移。

## 5. 结果

| Baseline | Precision | Recall | F1 | Hallucination Rate | FHIR Valid Rate | Tool Call Rate |
|---|---:|---:|---:|---:|---:|---:|
| B0 | 1.0000 | 0.6000 | 0.7500 | 0.6250 | 0.7500 | 0.0000 |
| B1 | 1.0000 | 1.0000 | 1.0000 | 0.2500 | 0.5000 | 0.1250 |
| B2 | 1.0000 | 1.0000 | 1.0000 | 0.0000 | 0.2500 | 0.3750 |
| B3 | 1.0000 | 1.0000 | 1.0000 | 0.2500 | 0.3750 | 0.6250 |
| B4 | 1.0000 | 1.0000 | 1.0000 | 0.2500 | 0.6250 | 0.6250 |

B0 对冲突样本的召回率仅为 0.6000，说明线性生成流程会遗漏视觉低质或文本-视觉矛盾样本，并导致 0.6250 的幻觉率。B2 通过 KG 门控把幻觉率降至 0.0000，但由于其采取保守审阅策略，FHIR 有效率仅为 0.2500。B4 在工具调用率 0.6250 的情况下，将 FHIR 有效率提升到 0.6250，说明 FHIR 修复工具对结构化输出有直接贡献。

自动生成的图表包括 `doctor/paper2/figures/paper2_summary_metrics.svg` 与 `doctor/paper2/figures/paper2_hallucination_fhir_tradeoff.svg`。前者集中展示 F1、幻觉率、FHIR 有效率和工具调用率，后者展示幻觉率与 FHIR 有效率之间的权衡关系。两张图均由 CSV 直接生成。

KG 传播消融生成 `doctor/paper2/experiments/results/kg_propagation.csv` 和 `doctor/paper2/experiments/reports/kg_propagation_report.md`。在 24 个 synthetic trial 上，signed-edge propagation 的冲突检出 Precision、Recall 和 F1 均为 1.0000；对应图表为 `doctor/paper2/figures/paper2_kg_propagation_scores.svg`。

实体映射覆盖率报告生成 `doctor/paper2/experiments/results/entity_map_coverage.csv` 和 `doctor/paper2/experiments/reports/entity_map_coverage_report.md`。当前 10/10 个 KG 实体具有 project-local 映射，覆盖率为 1.0000；FHIR target 覆盖率为 1.0000；所有 ICD/SNOMED 字段均为 `placeholder-only`。对应图表为 `doctor/paper2/figures/paper2_entity_map_coverage.svg`。为承接授权本体替换，本文新增 `run_ontology_identifier_audit.py`，会输出 `licensed_ontology_identifiers.template.csv`，并要求未来真实映射证据覆盖全部 KG 实体、提供授权状态、审批证据 URI、source release、artifact SHA-256，且不把受限本体原文提交到仓库。默认离线运行因没有真实 `licensed_ontology_identifiers.csv` 而保持 blocked。

message-passing embedding 消融生成 `doctor/paper2/experiments/results/graph_embedding.csv` 和 `doctor/paper2/experiments/reports/graph_embedding_report.md`。在同一 24 个 synthetic trial 上，其冲突检出 Precision、Recall 和 F1 均为 1.0000；对应图表为 `doctor/paper2/figures/paper2_graph_embedding_scores.svg`。

trainable graph-attention-lite 消融生成 `doctor/paper2/experiments/results/graph_attention.csv` 和 `doctor/paper2/experiments/reports/graph_attention_report.md`。在同一 24 个 synthetic trial 上，其冲突检出 Precision、Recall 和 F1 均为 1.0000；学习到的 support attention 为 -7.7959，contradiction attention 为 6.1827，low-quality attention 为 14.9607。对应图表为 `doctor/paper2/figures/paper2_graph_attention_scores.svg`。为避免把小型基线误报为投稿所需大图实验，本文新增 `run_large_gnn_evidence_audit.py`，会输出 `large_gnn_evidence.template.csv`，并要求未来真实证据包含许可证状态、非 placeholder 本体标识、节点/边规模、GNN/GAT 模型族、训练/验证/测试规模、指标值、evidence URI 和 artifact SHA-256。默认离线运行因没有真实 `large_gnn_evidence.csv` 而保持 blocked。

FHIR validator replay 生成 `doctor/paper2/experiments/results/fhir_validator_replay.csv`、`doctor/paper2/experiments/reports/fhir_validator_replay_report.md` 和 `doctor/paper2/experiments/fhir_bundles/`。该实验导出 120 个 Bundle JSON，并以 `local-structural` 模式批量校验；B0-B3 的 Bundle valid rate 均为 0.7500，B4 的 Bundle valid rate 为 1.0000。对应图表为 `doctor/paper2/figures/paper2_fhir_validator_replay.svg`。另有 official-validator audit 脚本生成 `official_fhir_validator_audit.csv`，记录 validator 命令、validator artifact SHA-256、local-valid Bundle 的外部通过数和 unexpected reject；默认离线运行因未配置官方 validator 命令和 jar artifact 而保持 blocked。

当前结果是 synthetic MVP 的内部有效性证据，不代表真实临床场景泛化能力。后续需要接入公开数据集、真实 FHIR validator 和人工评估协议。

数据集重放实验生成 `doctor/paper2/experiments/results/dataset_replay.csv` 和 `doctor/paper2/experiments/reports/dataset_replay_report.md`。在 24-trial 重放中，`sample_open_csv` 上 B0 的 F1 为 0.8000、幻觉率为 0.5000、FHIR 有效率为 0.8333；B4 的 F1 为 1.0000、幻觉率为 0.1667、FHIR 有效率为 0.6667。对应图表为 `doctor/paper2/figures/paper2_dataset_replay_rates.svg`。该实验只验证工程桥接能力，不构成真实公开数据集结论。

为承接真实公开/受控数据主实验，本文新增 `doctor/paper2/experiments/run_dataset_compliance_audit.py`。该脚本在不复制临床源记录的前提下，审计 registry 元数据、派生病例文件 schema、受控数据路径是否位于仓库外、基础 PHI 模式风险和审批证据字段。当前数据集合规审计显示，4 个 registry 条目中 2 个软件 fixture ready、2 个 controlled placeholder blocked；投稿所需 real dataset ready 为 0/2，submission-dataset-ready 为 no。该结果生成 `doctor/paper2/experiments/results/dataset_compliance_audit.csv`、`doctor/paper2/experiments/reports/dataset_compliance_audit_report.md` 和 `doctor/paper2/figures/paper2_dataset_compliance_audit.svg`。

专家评审协议验证生成 `doctor/paper2/experiments/expert_review/PROTOCOL.md`、`doctor/paper2/experiments/expert_review/review_packet.csv`、`doctor/paper2/experiments/expert_review/synthetic_annotations.csv` 和 `doctor/paper2/experiments/results/expert_review_agreement.csv`。当前包包含 40 个 review item 和 2 个 synthetic reviewer 的 80 条占位标注；`factually_supported` 与 `fhir_acceptable` 的 Cohen kappa 均为 1.0000，`needs_human_review` 的 Cohen kappa 为 0.8961。对应图表为 `doctor/paper2/figures/paper2_expert_review_agreement.svg`。该实验只验证盲审表结构和一致性统计脚本，不代表真实专家评审。

为承接后续真实专家评审，本文新增 `doctor/paper2/experiments/run_real_expert_review.py`。该脚本不会生成伪真实标注，而是从当前 review packet 输出 `real_annotations.template.csv`，并在真实专家填写 `real_annotations.csv` 后进行严格校验：至少两名非 synthetic reviewer、标注 item 必须来自 review packet、每个 item 至少两名 reviewer 覆盖、布尔字段必须合法、`overall_score` 必须在 1-5 范围内。只有通过校验后，脚本才会生成 `real_expert_review_agreement.csv` 与 `real_expert_review_report.md`，readiness audit 也只接受通过该校验的真实标注。

为承接真实 Gazebo/FR3 具身闭环，本文新增 `doctor/paper2/experiments/run_franka_closed_loop.py`。该脚本要求 `franka_api_server` 在线，先通过 `/status/joints` 与 `/motion/skills` probe，再通过 HTTP 执行具名 skill，并记录 `franka_closed_loop.csv` 中的 `probe_status`、`skill_success`、`latency_ms`、`joints_ok` 和 `skills_ok`。readiness audit 会校验这些字段，而不是仅凭 CSV 文件存在就认定机器人闭环完成。当前默认离线复现未连接 fake hardware/Gazebo 或 FR3，因此该 gate 仍为 blocked。

为确保中英文稿同步更新，本文新增双语论文同步审计 `doctor/paper2/experiments/run_bilingual_sync_audit.py`。该脚本不会尝试自动翻译，而是对中文 Markdown、英文 Markdown、中文 LaTeX、英文 LaTeX 和两份 PDF 做机械检查，确认两种语言都覆盖 synthetic MVP 范围、B0/B2/B4 关键指标、dataset replay、dataset compliance audit、placeholder-only entity map、授权本体标识审计、large-GNN/GAT 证据审计、FHIR replay、official-validator audit、真实专家评审模板、Franka API/Gazebo/FR3 闭环采集器、closed_loop_summary 延迟汇总、phase_completion_audit 阶段完成度审计、readiness 计数和 `submission-ready = no` 等关键证据。该结果生成 `doctor/paper2/experiments/results/bilingual_sync_audit.csv` 和 `doctor/paper2/experiments/reports/bilingual_sync_audit_report.md`。

M6 风格闭环延迟汇总由 `doctor/paper2/experiments/summarize_closed_loop.py` 生成。当前 120 trial 的 synthetic 本地闭环结果显示整体 latency p50 为 0.0420 ms、p95 为 0.0771 ms，工具调用率为 0.3500，并记录 initial/final route distribution。该结果只反映本地软件执行路径，不代表 Gazebo/FR3 实测 RTT。

为避免把软件原型误表述为投稿级完成，本文新增 readiness audit。`doctor/paper2/experiments/run_readiness_audit.py` 对数据集、授权本体标识、官方 FHIR validator、Franka API/Gazebo/FR3 闭环、大图 GNN/GAT、专家评审、双语论文产物、bilingual_sync_audit 内容同步和 phase_completion_audit 阶段完成度进行保守门控。默认离线复现结果显示，共 18 个 gate 中 ready 8 个、partial 1 个、blocked 9 个；投稿必需 gate 为 3/13 ready，submission-ready 为 no。phase_completion_audit 覆盖 35 项任务，其中 23 项 ready、11 项 partial、1 项 blocked；当前没有 submission-required 阶段任务 blocked。该结果生成 `doctor/paper2/experiments/results/readiness_audit.csv`、`doctor/paper2/experiments/reports/readiness_audit_report.md`、`doctor/paper2/experiments/results/phase_completion_audit.csv`、`doctor/paper2/experiments/reports/phase_completion_audit_report.md` 和 `doctor/paper2/figures/paper2_readiness_audit.svg`。

## 6. 讨论

该原型表明，论文 I 的边缘质量路由可以自然扩展到论文 II 的多模态语义冲突路由。关键不是让 LLM 在一次调用中完成所有判断，而是在状态机中显式保留证据、冲突分数和工具调用轨迹。这样，一旦上下文不完整或模态间不一致，系统会产生可审计的中间行为，而不是把不确定性隐藏在最终文本中。

不过，MVP 仍有明显限制。第一，数据是 synthetic，不能支撑临床结论；新增数据集重放层和合规审计只是接入真实公开/受控数据前的工程底座。第二，KG 是小型规则表，实体映射仍为 placeholder-only，graph-attention-lite 不是 ICD/SNOMED 大图模型；虽然已有大图 GNN/GAT 证据审计模板，但尚无真实授权大图训练证据通过审计。第三，FHIR replay 当前仍以本地结构校验为主，虽已具备外部 CLI 接口、批量 Bundle 导出和 official-validator audit gate，但尚未实际运行官方 validator jar。第四，专家评审当前只是 synthetic 协议验证；虽然已有真实标注模板和校验入口，但尚未邀请真实临床专家。第五，当前补拍是 synthetic 工具调用；虽然已有 Franka API/Gazebo/FR3 闭环采集器和证据校验，但尚未连接真实在线 API。第六，bilingual_sync_audit 只能证明中英文稿覆盖同一批关键证据，不能替代人工语言润色和期刊格式审校。readiness audit 将这些限制量化为 blocked gate，因此当前论文只能作为可复现 MVP 草稿，而不能作为最终临床或投稿结论。

---

## 7. 结论

本文完成了论文 II 的第一版可运行研究原型和双语论文证据基线。实验结果支持一个保守结论：在 synthetic 场景下，显式 KG 门控和工具调用机制能够把线性生成中的冲突遗漏转化为可审计路由，并为 EMR/FHIR 生成提供更强的事实约束。下一阶段应围绕公开数据集、官方 FHIR validator 复跑、许可证治理后的真实 GNN/GAT 图训练、真实 API/机器人闭环和真实专家审查继续推进。
