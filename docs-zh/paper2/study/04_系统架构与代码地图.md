# 04 · 系统架构与代码地图

---

## 1. 双仓分工（必须清楚）

| 仓库/目录 | 职责 | 论文角色 |
|-----------|------|----------|
| **`doctor/paper2`** | 多 Agent、KG、FHIR、实验脚本、主结果 | **主实验** B0–B4、消融、JSONL/CSV |
| **`franka_ros2`** | FR3 API、Edge-IQA 网关、Skills、ROS 桥接 | **具身工具层**、probe、未来真机闭环 |

> **一句话**：主图数字来自 `doctor/paper2` synthetic 矩阵；`franka_ros2` 提供论文 I 已有的 Edge-IQA 与 Skills 接口，供 Action Agent 未来真机调用。

## 2. 核心 API 端点（继承论文 I）

### 2.1 Vision Evaluate（Edge-IQA 网关）

```bash
POST /api/v1/vision/evaluate
Header: X-API-Key: franka-api-default-key
Content-Type: multipart/form-data   # file=@image.png
```

Paper II Vision Agent 在 MVP 中使用 synthetic 评分；真机联调时通过 `tools/franka_client.py` 调用此端点。

### 2.2 Skills API（具名位姿）

```bash
POST /api/v1/motion/skills/go_to_tongue_pose
POST /api/v1/motion/skills/go_to_face_pose
```

B3/B4 的 `execute_resample_tool()` 在 synthetic 模式下模拟调用；真机模式应走 HTTP client。

### 2.3 Readiness Probe

```bash
python3 doctor/paper2/tools/franka_probe.py
```

返回 `online` / `partial` / `offline`，用于 readiness audit，**不阻塞** synthetic MVP 运行。

## 3. 闭环数据流（一次 trial）

```
1. case 加载
   └─► 8 个 synthetic case 模板之一

2. symptom_agent
   └─► extract_symptom_entities(symptom_text)

3. vision_agent
   └─► evaluate_synthetic_vision(case) → q_img, vision_tags

4. kg_conflict_agent
   └─► compute_conflict_gate() → gamma_conflict, kg_matches

5. routing
   └─► decide_route(gate, baseline) → 六分支之一

6. action_agent（按需）
   ├─► execute_resample_tool() → go_to_tongue_pose（B3/B4）
   ├─► execute_followup_tool() → ask_followup
   └─► execute_kg_query_tool() → query_kg

7. emr_fhir_agent（generate_emr 时）
   ├─► build_emr_draft()
   ├─► build_fhir_bundle()
   ├─► validate_bundle()  ← tools/fhir_validator.py
   └─► repair_fhir_bundle()（B4）

8. JSONL 写盘
   └─► experiments/logs/paper2_run_001.jsonl
```

## 5. JSONL 审计字段（答辩可能被问）

每行 JSON 对应一个 `(case_id, baseline)` trial，关键字段：

```json
{
  "trial_id": "b2_trial_003",
  "case_id": "case_vision_blur",
  "baseline": "B2",
  "gamma_conflict": 0.412,
  "route_decision": "human_review",
  "final_route_decision": "human_review",
  "hallucination_flag": false,
  "fhir_valid": false,
  "tool_calls": [{"tool": "query_kg", "...": "..."}],
  "latency_ms": {"total": 42.5}
}
```

**审计价值**：任何论文表格数字都可追溯到具体 trial 行。

## 6. 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PAPER2_FHIR_VALIDATOR_CMD` | （空） | 外部 FHIR validator CLI 命令 |
| `FRANKA_API_HOST` | `127.0.0.1` | franka_client 目标主机 |
| `FRANKA_API_PORT` | `8000` | franka_client 目标端口 |
| `FRANKA_API_KEY` | （见 api_server 配置） | API 认证 |

Paper II **没有**类似 `PAPER1_MODE` 的全局开关；研究层与 API 层通过 HTTP 松耦合。
