## 2. 研究背景（用大白话）

### 2.1 问题场景

数字化诊疗需要把**主诉文本、视觉体征、机器人采集状态**汇成一份**结构化电子病历（EMR/FHIR）**。大模型可以「一次性生成」病历，但容易出现三类问题：

1. **模态冲突**：患者说「舌红」，图像标签却是「舌淡白」
2. **证据不足**：图像模糊、实体缺失，模型仍「补全」看似合理的临床断言
3. **不可追溯**：最终文本看起来通顺，但无法回溯到 KG 证据或工具调用

### 2.2 现有做法的问题

**Naive 做法**：把文本 + 图像丢给 LLM，一次调用生成 EMR/FHIR。

这带来三个痛点：

1. **幻觉（Hallucination）**：缺少证据时模型仍生成「合理但错误」的临床事实
2. **冲突遗漏**：线性流程不会主动检测文本-视觉-KG 不一致
3. **结构化输出脆弱**：FHIR Bundle 缺字段、引用错误，且无法自动修复

### 2.3 我们的思路

在**多 Agent 状态机**中显式保留证据链：

- 症状抽取 → 视觉评分 → **KG 冲突门控** → 路由决策
- 门控分数低 → **不直接生成病历**，而是补拍、补问、查 KG 或人工审阅
- 生成后 → **FHIR 校验 + 修复工具**（B4）

## 4. 四条贡献（投稿固定表述，必须背熟）

1. **架构贡献**：提出面向多模态 EMR 合成的 KG-gated multi-agent closed-loop 架构，将症状抽取、视觉评分、KG 冲突门控、具身工具调用和 FHIR 校验纳入同一状态对象（Paper2State）。
2. **工程贡献**：在 `doctor/paper2` 中实现可复现 synthetic MVP，生成 JSONL、CSV 和报告，证明研究管线已可运行（41 pytest + 120 JSONL 行）。
3. **实验贡献**：给出 B0–B4 五种基线，量化 KG 门控和工具调用对冲突检出 F1、幻觉率、FHIR 有效率的影响。
4. **边界贡献**：明确 `franka_ros2` 的工程边界——ROS 2/MoveIt/FastAPI/Skills 作为具身工具层，医学推理和论文主实验位于 `doctor/paper2` 研究层。

## 5. 本文聚焦 vs 不做

| 维度 | ✅ 本文做 | ❌ 本文不做（后续科研 / 博士他章） |
|------|----------|----------------------------------|
| 算法 | KG 门控、多 Agent 路由、FHIR 最小生成与修复 | 大规模真实 GNN/GAT 训练、临床 LLM 微调 |
| 数据 | 24 trial synthetic MVP；no-PHI 样例重放 | MIMIC-IV 等受控数据主实验（需 credentialing） |
| 架构 | 认知层 + 边缘 API + 具身 Skills | 完整 HIS/EMR 产品、K8s 运维 |
| 验证 | 本地结构 FHIR 校验、批量 Bundle replay | 官方 FHIR validator jar 实跑（接口已预留） |
| 评估 | synthetic 专家评审协议（kappa 统计） | 真实临床专家盲审（模板与校验脚本已就绪） |
| 硬件 | synthetic `go_to_tongue_pose` 补拍 | 真实 FR3/Gazebo/MoveIt 联调闭环 |

> **导师可能问**：「论文 II 和论文 I 是什么关系？」  
> **答**：论文 I 把 Edge-IQA 的 q_img 作为路由门控；论文 II **继承同一 LangGraph 范式**，把门控从「图像质量」升级为「多模态语义冲突 γ_conflict」，并扩展工具集（补问、查 KG、修 FHIR）。论文 I 的 `vision/evaluate` 和 `motion/skills` API 是论文 II Action Agent 的具身工具入口。

> **导师可能问**：「当前结果能投 SCI 一区吗？」  
> **答**：**不能**。readiness audit 显示投稿必需 gate 仅 1/11 ready。当前 MVP 证明**管线可跑通**，不能表述为临床有效性。详见 [03_实验数据与图表解读.md](./03_实验数据与图表解读.md) §6。
