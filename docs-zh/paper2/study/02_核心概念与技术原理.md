# 02 · 核心概念与技术原理

---

## 1. 三层架构

```
┌─────────────────────────────────────────────────────────┐
│  认知研究层（doctor/paper2）                              │
│  LangGraph 多 Agent、KG stub、FHIR 生成、实验脚本          │
│  Symptom / Vision / KG Conflict / Action / EMR-FHIR     │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP 工具调用（可选）
┌──────────────────────────▼──────────────────────────────┐
│  边缘 API 层（franka_api_server）                         │
│  /api/v1/vision/evaluate  → Edge-IQA（论文 I）           │
│  /api/v1/motion/skills/{name} → 具名位姿                 │
│  franka_probe.py → online/partial/offline 探测            │
└──────────────────────────┬──────────────────────────────┘
                           │ DDS / ROS 2
┌──────────────────────────▼──────────────────────────────┐
│  具身执行层（franka_*）                                   │
│  FR3 + MoveIt + Gazebo + ros2_control                    │
│  Skills：go_to_tongue_pose / go_to_face_pose             │
└─────────────────────────────────────────────────────────┘
```

**关键设计原则**：

- 医学推理、KG 门控、FHIR 生成**不进** 1 kHz ROS 控制循环
- 研究层通过**具名 Skill** 调用具身动作，不直接发送裸关节角
- 每个 trial 写入 JSONL，保证论文数字可回溯

## 2. 统一状态对象 Paper2State

所有 Agent 共享同一状态字典，核心字段：

| 字段 | 含义 |
|------|------|
| `trial_id` / `case_id` | 试验与病例标识 |
| `baseline` | B0–B4 之一 |
| `symptom_text` / `symptom_entities` | 主诉文本与抽取实体 |
| `q_img` / `vision_tags` | 图像质量与视觉标签 |
| `kg_matches` | KG 支持/矛盾边匹配 |
| `gamma_conflict` | 冲突门控综合分数 |
| `tau_gating` | 门控阈值（默认 0.65） |
| `route_decision` / `final_route_decision` | 路由决策 |
| `tool_calls` | 工具调用审计轨迹 |
| `emr_draft` / `fhir_bundle` / `fhir_valid` | EMR 草稿与 FHIR 校验 |
| `hallucination_flag` | 是否产生幻觉 |
| `latency_ms` | 各阶段耗时 |

代码位置：`doctor/paper2/langgraph_router/state.py`

## 3. 五个 Agent 与职责

| Agent | 文件 | 输入 | 输出 |
|-------|------|------|------|
| **Symptom Agent** | `agents/symptom_agent.py` | 主诉文本 | `symptom_entities`、实体完整度 |
| **Vision Agent** | `agents/vision_agent.py` | case 模板 | `q_img`、`vision_tags` |
| **KG Conflict Agent** | `agents/kg_conflict_agent.py` | 实体 + 视觉标签 + KG | `gamma_conflict`、`kg_matches` |
| **Action Agent** | `agents/action_agent.py` | 路由决策 | `execute_skill` / `ask_followup` / `query_kg` |
| **EMR/FHIR Agent** | `agents/emr_fhir_agent.py` | 完整 state | `emr_draft`、`fhir_bundle` |

### 3.1 一次 trial 的执行顺序

```
case 输入
  → extract_symptom_entities()
  → evaluate_synthetic_vision()
  → compute_conflict_gate()
  → decide_route()
  → [可选] resample / followup / query_kg
  → [可选] build_emr_draft() + validate_bundle() + repair_fhir()
  → 写入 JSONL
```

## 4. KG 冲突门控（核心公式，必须背）

\[
\gamma_{conflict} = 0.28 \cdot C_{entity} + 0.24 \cdot Q_{vision} + 0.36 \cdot C_{kg} - 0.22 \cdot P_{contradict}
\]

| 分量 | 含义 | 范围 |
|------|------|------|
| \(C_{entity}\) | 实体完整度（期望实体是否都被抽取） | [0, 1] |
| \(Q_{vision}\) | 视觉质量（= q_img） | [0, 1] |
| \(C_{kg}\) | KG 一致性（支持边 − 矛盾边） | [0, 1] |
| \(P_{contradict}\) | 矛盾惩罚（文本-视觉 KG 矛盾边权重） | [0, 1] |
| \(\tau_{gating}\) | 门控阈值 | **0.65**（默认） |

**物理含义**：\(\gamma \geq \tau\) 且路由允许 → 可生成 EMR；否则进入补拍/补问/查 KG/人工审阅。

代码：`doctor/paper2/agents/kg_conflict_agent.py::compute_conflict_gate()`

> 详见 [06_KG门控与GNN基线详解.md](./06_KG门控与GNN基线详解.md)

## 5. 路由决策（六分支，必须背）

路由函数：`doctor/paper2/langgraph_router/routing.py::decide_route()`

| 决策 | 触发条件（简化） | 后续动作 |
|------|-----------------|----------|
| `generate_emr` | γ ≥ τ，无严重冲突 | 生成 EMR/FHIR |
| `resample_vision` | q_img < 0.55，B3/B4 | 调用 `go_to_tongue_pose` 补拍 |
| `ask_followup` | 实体不完整 | 生成追问问题 |
| `query_kg` | 矛盾惩罚 ≥ 0.5 或 γ < τ | 查询 KG 证据 |
| `repair_fhir` | B4 且 FHIR 校验失败 | 补齐 Observation 等 |
| `human_review` | B2 低质 / 超限 / B4 补问后 | 挂起人工审阅 |

**与论文 I 的对应**：

| 论文 I | 论文 II |
|--------|---------|
| `upload_cloud` | `generate_emr` |
| `resample_edge` | `resample_vision` |
| `fail_safe` | `human_review` |
| 门控：\(Q_{img} \geq \tau\) | 门控：\(\gamma_{conflict} \geq \tau_{gating}\) |

## 6. 五种基线 B0–B4

| 基线 | 名称 | 门控 | 具身补拍 | FHIR 修复 | 典型用途 |
|------|------|------|----------|-----------|----------|
| **B0** | Linear EMR | ❌ | ❌ | ❌ | Naive 一次生成（对照） |
| **B1** | Self-Reflection | 浅层（质量+完整度） | ❌ | ❌ | 无 KG 的自反思 |
| **B2** | KG-Gated | ✅ KG 门控 | ❌（低质→人工） | ❌ | **KG 门控主方法** |
| **B3** | Embodied Closed Loop | ✅ | ✅ 补拍 | ❌ | KG + 具身自愈 |
| **B4** | Tool-Enhanced | ✅ | ✅ | ✅ repair_fhir | **完整工具链** |

### 6.1 各基线路由差异（关键）

- **B0**：永远 `generate_emr`，不做任何门控 → 高幻觉率
- **B1**：仅按 q_img 和实体完整度做浅层路由，**不用 KG**
- **B2**：完整 KG 门控，但视觉低质 → `human_review`（不补拍）
- **B3**：B2 + 低质时 `resample_vision`（synthetic 补拍提升 q_img）
- **B4**：B3 + FHIR 校验失败时 `repair_fhir` + 补问后仍挂人工审阅

## 7. 评估指标

| 指标 | 定义 | MVP 主结果关注点 |
|------|------|-----------------|
| **Conflict F1** | 冲突检出的 P/R/F1 | B0=0.75 → B2=1.00 |
| **Hallucination Rate** | 有冲突标签却直接生成 EMR 的比例 | B0=0.625 → B2=0.000 |
| **FHIR Valid Rate** | 本地结构校验通过率 | B2=0.25 → B4=0.625 |
| **Tool Call Rate** | 触发工具调用的 trial 比例 | B0=0 → B4=0.625 |
| **Latency** | 闭环总耗时 | JSONL 中 `latency_ms.total` |

**核心权衡**：B2 把幻觉率压到 0，但 FHIR 有效率仅 0.25（保守审阅策略）；B4 用工具调用换 FHIR 有效率提升。

## 8. 幻觉判定逻辑

```python
# graph.py 简化逻辑
hallucination_flag = conflict_label and (route == "generate_emr")
if baseline == "B0" and conflict_label:
    hallucination_flag = True  # B0 对冲突样本几乎必然幻觉
```

**含义**：ground truth 标记为冲突的 case，若系统仍走 `generate_emr`，计为幻觉。

## 9. 与论文 I 的技术继承

| 论文 I 组件 | 论文 II 复用方式 |
|-------------|-----------------|
| Edge-IQA (`q_img`) | Vision Agent 的质量输入；B3/B4 补拍前后对比 |

| LangGraph 状态图范式 | 从单模态路由扩展为多 Agent 多轮 |
| JSONL 审计 | 同一证据链思路，字段扩展为 Paper2State |

## 10. 当前 MVP 限制（口述必备）

1. **数据 synthetic**：8 case 模板 × 24 trial，非真实临床
2. **KG 为小型 stub**：`kg/kg_stub.json`，非 SNOMED/ICD 大图谱
3. **补拍为 synthetic**：`resample_vision()` 直接提升 q_img，非真机
4. **FHIR 官方校验仍 blocked**：已有 official audit gate，但未运行官方 validator jar
5. **专家评估为 synthetic placeholder**：非真实医生盲审
