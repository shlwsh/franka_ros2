# 各角色审核细则（Paper I 专版）

> **用途**：Phase 1–2 各角色按序勾选，减少漏审与重复劳动。
> **前提**：先读 [config.md](config.md) 确认 `PAPER1_ROOT`、主稿和 `TARGET_JOURNAL`；数值以 `experiments/results/*.json` 为准。
> **投稿模式**：RA-L / RCIM 检查见 [期刊投稿要点.md](期刊投稿要点.md)。
> **重大修改/二次评审**：见 [基准论文对照与改稿闭环.md](基准论文对照与改稿闭环.md)。

## 0. 多稿同步矩阵（全角色共用）

| 层级 | 路径 | 审核作用 |
|------|------|----------|
| **L0 实验真相** | `experiments/results/*.json` | Abstract、Table II、图表与结论数字必须可追溯到 JSON 字段 |
| **英文主稿** | `latex/main.tex`、`latex/main-ral.tex`、`latex/sections/*.tex` | 默认盲审主对象 |
| **中文稿** | `latex/main-zh.tex`、`latex/sections/zh/*.tex` | 术语、图表、摘要与数值同步抽查 |
| **投稿材料** | `submission/**` | Cover letter、CRediT、图形摘要、声明 |
| **引用归档** | `data/papers/`、`latex/references.bib` | 可审计引用、PDF/快照、引用审计结果 |
| **学习手册** | `docs/study/` | 领域背景、投稿策略、导师问答，可辅助但不得替代原稿证据 |

**预检建议命令（Phase 1 / 统计 / 编辑）**：

```bash
PAPER1_ROOT=doctor/paper1
find "$PAPER1_ROOT/experiments/results" -maxdepth 1 -name '*.json' -print | sort
grep -c '\\paragraph' "$PAPER1_ROOT/latex/sections/05_5_discussion.tex"
grep -Ei 'faq|reviewer faq|待填|TODO' "$PAPER1_ROOT/latex" "$PAPER1_ROOT/submission" 2>/dev/null || true
grep -E '[0-9]+(\\.[0-9]+)? *ms|M1|M2|tau|τ' "$PAPER1_ROOT/latex/sections/00_abstract.tex" "$PAPER1_ROOT/latex/sections/table_ii.tex" 2>/dev/null || true
python3 "$PAPER1_ROOT/scripts/check_paper1_refs.py"
python3 "$PAPER1_ROOT/scripts/paper1_audit_papers.py"
```

**典型反模式（历史会话沉淀）**：

| 反模式 | 后果 | 负责角色 |
|--------|------|----------|
| Abstract、Table II、Cover Letter 中 M1/M2/τ 数值不同步 | P0 数值事故 | 📊 🔍 ✍️ |
| 英文稿改了贡献或实验，中文稿未同步 | 双语稿漂移 | ✍️ 📚 |
| 把合成退化实验外推为临床真实场景结论 | 领域与伦理风险 | 🔬 📐 |
| Edge-IQA、B3、NIQE/BRISQUE 等基线条件不同却直接强比较 | 公平性质疑 | 🔍 📊 |
| RA-L 压缩稿仍保留过多实验碎片或 FAQ 式段落 | 篇幅和体例不合格 | ✍️ |
| 引用 PDF 与 bib key 不匹配，或 DOI/URL 不可核实 | 可审计性不足 | 📐 📚 |
| 改稿只更新 `main.tex`，未更新 `main-ral.tex`、`main-zh.tex` 或投稿材料 | 版本不可控 | ✍️ 🎯 |

## 1. Phase 1 — 📚 预检员细则

**目标**：快速锁定 P0，输出 `01-预检报告.md`。
**输出格式**：每条 `ID | P0/P1/P2 | 文件:行 | 描述 | 证据字段/命令`。

### C1 结构与篇幅

| 检查项 | 命令/方法 | 通过标准 |
|--------|-----------|----------|
| 实验子节数量 | `grep -c '\\input{sections/05' latex/main.tex` | RA-L 稿应聚焦，过多辅轨进入补充材料 |
| Discussion 碎片化 | `grep -c '\\paragraph' latex/sections/05_5_discussion.tex` | 讨论为连贯段落，FAQ 式小标题降到最低 |
| RA-L 主稿 | 读 `latex/main-ral.tex` | 压缩版存在且与主稿核心结论一致 |

### C2 数值一致性（最高优先级）

| 位置 | 必核字段 | 通过标准 |
|------|----------|----------|
| `table_ii*.json` | M1 / M2 / Valid Rate / tau 等 | 作数值基准 |
| `00_abstract.tex` | 摘要核心数字 | 与 JSON / Table II 一致 |
| `table_ii.tex` / `table_iii.tex` | 表格数字与单位 | 与 JSON 一致，单位清楚 |
| `submission/**` | Cover letter、图形摘要 | 不出现旧数字或旧术语 |

### C3 参考文献与归档

| 检查项 | 通过标准 |
|--------|----------|
| bib 键与正文引用 | 无未定义引用；`check_paper1_refs.py` exit 0 |
| RA-L 引用审计 | `paper1_audit_papers.py` 生成 `data/papers/cite_audit.json` |
| DOI / URL | 关键引用有可核实 DOI 或 URL |
| PDF/快照 | 见 [参考文献归档细则.md](参考文献归档细则.md) |

### C4 非学术段落与占位符

| 检查项 | 通过标准 |
|--------|----------|
| FAQ / reviewer 备注 | 正文无 |
| 作者/基金/邮箱 | 无匿名或待填占位，除非目标要求匿名 |
| AI 辅助声明 | 稿末或投稿材料中有明确声明 |

### C5 编译与交叉引用

| 检查项 | 通过标准 |
|--------|----------|
| 编译 | 使用现有构建脚本或 latexmk；若未运行，说明原因 |
| `\ref{}` / `\label{}` | `check_paper1_refs.py` 无 missing labels |
| 图表 caption | 所有 figure/table 有 caption 且正文引用 |

### C6–C10 深度预检

| ID | 检查 | 触发 P0/P1 条件 |
|----|------|----------------|
| C6 | 算法形式化 | Edge-IQA、置信度路由或闭环状态机缺伪代码/状态转移/参数定义 |
| C7 | 基线公平性 | B0–B3、NIQE/BRISQUE/B3 条件不清或测量点不一致 |
| C8 | 统计呈现 | 无方差/置信区间/seed 说明，或图表缺误差条 |
| C9 | 图文一致 | 图注、正文、表格与 JSON 任一核心数字冲突 |
| C10 | 三贡献贯穿 | 摘要、引言、方法、结论中的三贡献表述不一致 |

### T1–T7 投稿前检查（`TARGET_JOURNAL`）

| ID | 检查 | 通过标准 |
|----|------|----------|
| T1 | RA-L 篇幅 | 主稿页数、参考文献、附录处理符合当前模板要求 |
| T2 | IEEE 格式 | 图表、引用、声明、作者信息符合目标模板 |
| T3 | 机器人贡献 | 机器人闭环采集价值不是单纯图像分类指标 |
| T4 | 医学/TCM 声称 | 不把技术验证写成临床诊断有效性结论 |
| T5 | 复现材料 | 代码、数据、脚本和仿真/假硬件边界说明清楚 |
| T6 | 双语同步 | 中文稿与英文稿核心术语、数字、图表一致 |
| T7 | 投稿材料 | Cover letter、CRediT、AI/COI 声明齐全 |

- 核心数字与 JSON 不一致，或结论无法追溯到表格/实验数据；
- Baseline 条件不公平却作强结论；
- 关键算法缺形式化描述或与代码/实验不对应；
- 声称临床/机器人部署有效性但只提供离线或仿真证据；
- τ、split、seed、硬件/网络配置不透明。

**必核计算（逐项打勾）**：

| # | 检查 | 方法 |
|---|------|------|
| S1 | Table II 数字 | JSON 字段 → LaTeX 表格 → Abstract |
| S2 | seed / split | train/val/test 是否固定且无泄漏 |
| S3 | τ 标定 | 阈值来自训练/验证，不从测试集挑最优 |
| S4 | 方差/置信区间 | `table_ii_bootstrap.json` 或表内 ± / CI |
| S5 | 多重比较 | 多 baseline、多指标时避免选择性报告 |
| S6 | 失败案例 | error cases 是否支持统计结论边界 |
| S7 | 图表一致 | 图中数值、caption、正文描述一致 |
| S8 | 真实/仿真分轨 | 离线、仿真、硬件闭环不可混为同一证据 |
| S9 | 效应量 | 不只给 p 值，说明实际收益和代价 |
| S10 | 样本量 | 数据集规模、图像级/患者级独立性是否说明 |

**Major 触发**：任一主表数字与 JSON 差异无法解释；测试集泄漏风险；方差/CI 缺失导致核心 claim 不可判断；图文数据冲突。

## 8. PI 裁决与行动清单规范

**P0 上限 7 条**；每条必须含：

- 可执行 `验收标准`（grep / JSON 字段 / 审计脚本 / 编译命令）
- `需同步文件` 列表（英文主稿 + RA-L 稿 + 中文稿 + submission）

**优先级映射**：

| 类型 | 典型优先级 |
|------|------------|
| 摘要/表格/JSON 核心数字不一致 | P0 |
| 引用不可核实、bib key 错误 | P0/P1 |
| 基线公平性或测试集泄漏风险 | P0 |
| RA-L 篇幅、结构过散 | P1 |
| 前沿文献覆盖不足、局限过浅 | P1 |
| 图表/术语/语言润色 | P2 |

## 9. 高效审核时间盒（推荐）

| 阶段 | 时间 | 产出 |
|------|------|------|
| Phase 0 | 5 min | `00-上下文清单.md` |
| Phase 1 | 15 min | `01-预检报告.md` |
| Phase 2 x5 | 各 10–15 min | `02-*.md` 五份 |
