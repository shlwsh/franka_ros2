# RA-L / RCIM 投稿要点

> **用途**：多角色审核时，以目标期刊口径检查篇幅、格式、贡献定位、声明和投稿材料。
> **边界**：本文件只记录本技能的审核动作；投稿前必须由作者打开目标期刊官网核对最新 author instructions。
> **RA-L 官方入口**：https://www.ieee-ras.org/publications/ra-l/ra-l-information-for-authors/

---

## 0. 与审核技能的映射

| 要求类别 | 主责角色 | 预检 / Issue ID |
|----------|----------|-----------------|
| 原创、双匿名、无一稿多投、AI/COI 声明 | 📐 伦理 | T4 / T7 / ETHICS-T* |
| 机器人与自动化贡献 | 🔬 领域 + 🔍 方法 | T3 / DOMAIN-T* |
| 方法可复现、实验充分 | 🔍 方法 + 📊 统计 | C6–C9 / METHOD-T* |
| 篇幅、模板、图表、引用 | ✍️ 编辑 | T1–T2 / EDIT-T* |
| 双语同步、PaperCept 材料、R&R 产物 | ✍️ + 📚 | T6–T9 |
| 视频、代码、数据等多媒体 | 🔍 + 📐 + ✍️ | T5 / T10 |

当用户指定 `TARGET_JOURNAL=RAL` 或“投 RA-L”时，Phase 1 追加 T1–T10；当用户指定 RCIM 时，沿用 T1–T7 但弱化 RA-L 页数、强化工业/系统可复现叙事。

## 1. RA-L 硬门槛（投稿前必查）

| 门槛 | 审核动作 | 触发 Issue |
|------|----------|------------|
| **篇幅** | 初稿按 6 页双栏审；确需超页时最多按 8 页上限评估，且记录超页理由 | EDIT-RAL-PAGE |
| **双匿名** | 投稿稿删除作者、单位、致谢、项目号、可识别代码链接；自引用用第三人称 | ETHICS-RAL-ANON |
| **PaperCept** | 记录目标入口 `ras.papercept.net/journals/ral`；检查 PDF、关键词、conference option、multimedia | EDIT-RAL-SUBMIT |
| **R&R 周期** | 若为 revise-and-resubmit，方案必须支持 30 天内完成；输出 Author Response 与带标注差异稿 | PI-RAL-RR |
| **Final 硬截止** | 接收后最终稿、版权、费用、可选视频等须能 2 周内交付 | EDIT-RAL-FINAL |
| **多媒体限制** | 视频/代码/数据可提交；不得用补充文本规避主文页数；主文必须自洽 | METHOD-RAL-MM |
| **PDF 质量** | 字体嵌入、图表清晰、双栏无溢出；优先用 IEEE PDF 检查工具 | EDIT-RAL-PDF |
| **生成式 AI** | 若使用 AI 辅助写作/翻译/代码，按 IEEE/RAS 政策披露并保留作者责任 | ETHICS-RAL-AI |

## 2. RA-L 论文质量细则

| 类别 | 审核动作 |
|------|----------|
| Timely | 摘要和引言说明为什么现在需要该结果，不写成长期综述或工程记录 |
| Concise | 6 页内呈现核心发现；每节只保留支撑贡献的证据 |
| Innovative | 明确回答 What is new / why important / how better，给出可量化 delta |
| 机器人贡献 | 引言、系统、实验必须体现机器人闭环采集，而非普通 IQA 离线分类 |
| 技术严谨性 | Edge-IQA、routing、τ、B0–B3 基线可复现，数据源与测量点明确 |
| 真实验证 | RA-L 偏好真实机器人/自动化实验证据；仿真和离线实验必须标注边界 |
| 统计与公平性 | 重复实验、误差条/置信区间、SOTA/strong baseline、公平配置 |
| 图表 | 图中文字可读，caption 自包含，表格不溢出且引用齐全 |
| 声明 | AI、COI、data/code availability、CRediT / author contribution 与投稿材料一致 |
| 语言 | IEEE 风格简洁；避免营销语、过度临床承诺、过长贡献句 |

### RA-L 常见风险

| 风险 | 触发 Issue |
|------|------------|
| 页数超限或实验章节过碎 | EDIT-T1 |
| 机器人自动化贡献被 IQA 指标淹没 | DOMAIN-T3 |
| 主结论只来自离线数据，闭环演示弱 | METHOD-T1 |
| 表格/图注需要靠正文才能理解 | EDIT-T2 |
| 声称临床诊断有效性 | ETHICS-T4 |
| 双匿名稿暴露作者或项目身份 | ETHICS-RAL-ANON |
| 没有高质量机器人视频计划 | METHOD-RAL-VIDEO |
| R&R 方案无法 30 天完成 | PI-RAL-RR |

## 3. RA-L 审稿表对齐

Phase 5 必须把主要结论映射到 RA-L 审稿人常评维度：

| 维度 | 高质量稿标准 | 低分触发 |
|------|--------------|----------|
| Originality / Novelty | 方法、系统或实验结论有清楚新意，非小调参 | 仅工程集成或 incremental |
| Technical Quality | 数学/算法/系统描述可复现，假设和边界明确 | 方法含糊、关键参数不可追溯 |
| Significance | 对机器人/自动化问题有明确影响 | 机器人场景只是包装 |
| Experimental Validation | 真实机器人/自动化证据 + 公平 baseline + 统计 | 无硬件、弱 baseline、无误差 |
| Presentation | 摘要、图表、caption、英语和结构清晰简洁 | 超页、图表不可读、叙事散 |
| Reproducibility / Ethics | 数据、代码、视频、AI/COI、匿名合规 | 归档缺失或披露不足 |

## 4. RCIM 口径重点

| 类别 | 审核动作 |
|------|----------|
| 制造/自动化系统价值 | 强调机器人采集、边缘部署、流程效率和系统工程可复现性 |
| 工业可用性 | 说明硬件、网络、部署边界、失败模式、维护成本 |
| 实验充分性 | 相比 RA-L 可容纳更完整的消融、失败案例、工程细节 |
| 写作结构 | 叙事可更展开，但仍需避免堆砌所有辅助实验 |

### RCIM 常见风险

| 风险 | 触发 Issue |
|------|------------|
| 自动化/制造系统意义不清 | DOMAIN-RCIM1 |
| 只给算法指标，缺部署与流程指标 | METHOD-RCIM1 |
| 代码/数据/硬件环境不可复现 | ETHICS-RCIM1 |

## 5. 投稿前检查清单（写入 `05` 附录）

- [ ] 目标期刊和模板已由作者确认，主稿文件明确；
- [ ] RA-L 稿按 6 页目标压缩；若为 7–8 页，说明加页理由；
- [ ] 双匿名稿删除作者、单位、致谢、基金、可识别链接；
- [ ] Abstract 150–250 词左右，包含问题、贡献、方法亮点、核心结果、意义；
- [ ] Keywords 3–6 个，优先选择 RA-L / IEEE 机器人相关关键词；
- [ ] Title 具体简洁，能显示关键技术和机器人/自动化对象；
- [ ] Abstract、Title、Keywords、AI/COI/Data availability 一致；
- [ ] RA-L 压缩稿 `main-ral.tex` 与 `main.tex` 核心结论一致；
- [ ] 图表 caption、正文引用、参考文献格式已检查；
- [ ] Table II / Abstract / Cover Letter 核心数字与 JSON 一致；
- [ ] 机器人闭环贡献、Edge-IQA、confidence-aware routing 三贡献贯穿；
- [ ] 至少有真实机器人/自动化演示证据；仿真/离线结果边界明确；
- [ ] Video / code / data / multimedia 是否提交已有明确计划；
- [ ] 临床/TCM 表述不过度外推；
- [ ] 新增引用均可核实并归档或记录缺失原因；
- [ ] 投稿材料不含内部备注、TODO、旧版本数字；
- [ ] 若为 R&R，Author Response、Diff manuscript、30 天计划齐全。

## 6. 自动化辅助命令

```bash
PAPER1_ROOT=doctor/paper1

# 主稿存在
test -f "$PAPER1_ROOT/latex/main-ral.tex" && echo OK main-ral
test -f "$PAPER1_ROOT/latex/main.tex" && echo OK main

# 摘要/关键术语
grep -n "Confidence-Aware\\|Edge-IQA\\|Valid Rate\\|TCM\\|tongue" \
  "$PAPER1_ROOT/latex/sections/00_abstract.tex" \
  "$PAPER1_ROOT/latex/sections/01_intro.tex"

# 双匿名风险
grep -Ein "author|affiliation|acknowledg|grant|fund|anonymous|github.com/.*/paper1|太原理工|shihonglei" \
  "$PAPER1_ROOT/latex/main-ral.tex" "$PAPER1_ROOT/latex/sections" "$PAPER1_ROOT/submission" 2>/dev/null || true

# 非学术/占位符
grep -Ein "reviewer faq|faq|todo|待填|国内领先|唯一|产品" \
  "$PAPER1_ROOT/latex" "$PAPER1_ROOT/submission" 2>/dev/null || true

# 图表 caption 与引用粗查
grep -R "\\\\caption" "$PAPER1_ROOT/latex/sections" | wc -l
python3 "$PAPER1_ROOT/scripts/check_paper1_refs.py"
```

## 7. 各角色投稿增量必答

| 角色 | 投稿增量问题 |
|------|--------------|
| 🔬 | 机器人/自动化读者为何关心？TCM/医学外推是否克制？近年 IQA/机器人采集文献是否足够？ |
| 🔍 | 主张是否有实验或形式化支撑？B0–B3 是否公平？闭环实现是否真实可复现？视频能否展示机器人闭环？ |
| 📊 | n、split、CI、bootstrap、τ 标定是否支撑主结论？6 页内是否保留最有判别力的数据？ |
| ✍️ | 篇幅、图表、摘要、关键词、双匿名、投稿材料是否统一？ |
| 📐 | AI/COI/Data availability、数据许可、临床声明、双匿名和多媒体披露是否合规？ |
| 🎓 | 若 T1/T3/T4 或 C2/C7 不通过，倾向 Major Revision；若 R&R，必须能 30 天闭环。 |
