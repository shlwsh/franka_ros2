# 基准论文对照与改稿闭环

> **用途**：当用户要求“按评审意见改稿”“重大修改”“二次评审”“对照某几篇基准论文”时，必须使用本清单。
> **基准来源**：优先使用用户提供的论文；其次使用 `data/papers/`、`docs/study/09_期刊选择与投稿策略.md` 或领域审稿报告中列出的关键 RA-L / RCIM / IQA / robotic acquisition 文献。不得臆造具体论文结论。

---

## 1. 八维度对照门槛

评审报告与改稿方案至少覆盖以下 8 个维度；每个维度必须给出 `差距`、`修改动作`、`验收标准`、`涉及文件`。

| 维度 | 对照重点 | 主责角色 | 稿件验收标准 |
|------|----------|----------|--------------|
| 结构与逻辑 | 基准论文如何组织问题、方法、实验、讨论 | ✍️ 🎓 | 摘要/引言/系统节形成清晰闭环叙事 |
| 文献综述与定位 | IQA、edge AI、robotic acquisition、TCM tongue imaging 覆盖是否充分 | 🔬 | `02_related.tex` 有分项对比和本文定位 |
| 技术创新 | Edge-IQA + confidence-aware routing 是否凝练为可复用框架 | 🔍 🔬 | 三贡献在摘要、引言、结论一致 |
| 实验严谨性 | 基线、公平性、split、CI、失败案例 | 📊 🔍 | `05_*` 含效度威胁、方差/CI、复现路径 |
| 写作与呈现 | 图表、摘要、术语、篇幅 | ✍️ | RA-L 稿紧凑，图表自包含且不溢出 |
| 实用性与部署 | 机器人闭环、网络、边缘算力、ROS 2 / Franka 场景 | 🔬 🔍 | 部署边界、失败模式、实时性证据明确 |
| 算法与实现深度 | τ、状态机、复杂度、退化策略、代码路径 | 🔍 | 方法节含形式化描述并能映射实现 |
| 未来工作与伦理 | 临床边界、数据开放、AI/COI、隐私 | 📐 🎓 | 结论和声明不过度承诺，限制清楚 |

---

## 2. 改稿闭环要求

当用户要求“根据评审意见改稿/实现改进/二次评审”时，执行以下闭环：

1. **方案先落盘**：在 `{PAPER1_ROOT}/docs/` 下生成带时间戳的改进方案，命名形如 `YYYYMMDD-HHMMSS-重大修改改进方案.md`。
2. **修改主稿**：同步修改 `latex/main.tex`、`latex/main-ral.tex`、`latex/main-zh.tex`、`latex/sections/*.tex`、`latex/sections/zh/*.tex` 和 `submission/**` 中受影响材料。
3. **数值门禁**：任何涉及 M1/M2/Valid Rate/τ/样本量/seed 的改动，必须回查 `experiments/results/*.json`。
4. **引用门禁**：新增 `\cite{}` 后运行引用/归档审计，更新 `data/papers/` 或记录缺失原因。
5. **版本化编译**：成功编译后，将 PDF 另存为带版本号和时间戳的文件，例如 `docs/v{N}-paper1-ral-YYYYMMDD-HHMMSS.pdf`；历史 PDF 不删除。
6. **二次评审**：对修改后稿件执行轻量 Phase 0–5 回归，至少输出 `docs/YYYYMMDD-HHMMSS-二次评审报告.md`，含上一轮问题关闭情况与剩余风险。
7. **验证记录**：记录编译命令、PDF 路径、审计脚本、`git diff --check`；若未能编译或验证，必须说明原因。

---

## 3. 二次评审重点

二次评审不重复生成完整 `reviews/{run_id}/` 时，最少检查以下项：

| ID | 检查项 | 通过标准 |
|----|--------|----------|
| R1 | P0 是否关闭 | 每个 P0 有验收命令或证据 |
| R2 | 八维度建议是否落稿 | 每维至少 1 个正文或方案响应 |
| R3 | 数值一致 | Abstract / Table II / Cover Letter / JSON 一致 |
| R4 | 基线与统计 | split、CI、τ、baseline 公平性无新风险 |
| R5 | 引用归档 | 新增引用已审计 |
| R6 | 表格不溢出 | 新增/扩展表格适配单栏/双栏格式 |
| R7 | 版本化文稿 | `docs/` 中存在本轮带版本号 PDF |
| R8 | 历史保留 | 不删除旧稿、旧评审和旧时间戳文件 |

---

## 4. Cover Letter / Response 对应关系

重大修改完成后，建议生成或更新 cover letter / response letter，至少包含：

- 对编辑或审稿人主要意见的逐项回应；
- 新增/修改的章节、图表、表格和脚本路径；
- 未新增真实临床/大规模实验时的原因、边界和计划；
- 代码、数据、Docker/ROS 2/Franka 复现材料的公开计划；
- 与基准论文的互补关系：本文解决自动采集前端质量控制与边缘路由，不替代临床诊断模型或完整医疗验证。
