# Goal

统一 `docs/`、`doctor/paper1/docs/` 目录及其子目录下所有方案和设计报告的文档命名规范，强制添加版本号和时间戳。

## Instructions

1. **识别触发条件**：
   - 检查目标路径是否为 `docs/`、`doctor/paper1/docs/` 或其子目录（如 `docs-zh/`、`doctor/paper1/docs/study/` 等）。
   - 检查要输出的文档内容类型是否属于“方案”或“设计报告”。
2. **格式化文档名称**：
   - 命名格式严格遵循：`v<版本号>_<YYYYMMDD>_<文档简短描述>.md`。
   - `版本号`：初始默认为 `1.0`。如果是对已有方案的更新，请在原版本号基础上递增（例如 `v1.1`）。
   - `时间戳`：使用当天的真实日期，格式为 `YYYYMMDD`（如 `20260611`）。
   - `文档简短描述`：使用简明扼要的中文或英文名词短语概括核心内容（例如 `系统架构设计方案`）。
   - 示例组合：`v1.0_20260611_系统架构设计方案.md`。
3. **静默修正**：
   - 如果用户口语中提供了不规范的文件名（如 `架构方案.md`），请自动将其转化为上述规范形式再执行保存。
4. **内部文档元数据对齐**：
   - 确保所生成文档的 Markdown 标题（一级标题 `#`）或文档开头区域也包含相应的版本号和日期信息，使其与文件名保持一致。

## Examples

具体示例请参考 `examples/` 目录下的案例文件。

## Constraints

- 此规范仅对方案（Scheme）和设计报告（Design Report）类型的文档生效。
- 不得应用于常规说明（如 `README.md`、`index.rst`、开源协议）、学术论文 LaTeX 文件、配置文件及代码文件。
- 文件名中的下划线 `_` 作为分隔符不可省略。
- `SKILL.md` 内容必须使用中文编写。
