## Major Issues

### METHOD-M1: Edge-IQA 方法创新性不足，贡献声称过强
- **位置**: `04_1_edge_iqa.tex` L7-11
- **证据**: Eq.(1) 仅为 Laplacian variance 与 exposure 的加权融合，权重固定 0.65/0.35
- **问题**: Edge-IQA 的核心公式 $Q_{img} = 0.65S + 0.35E$ 本质是两个经典特征的线性组合，技术新颖性有限。Abstract 和 Introduction 将其包装为一个"contribution"，但实际上这是工程集成而非算法创新。
- **建议**: 将贡献定位调整为"系统集成贡献"而非"算法贡献"；或增加与 BRISQUE/NIQE 在相同 LangGraph 路由下的定量对比（目前仅在 Table I 做定性比较）。
- **修改 sketch**: 在 `01_intro.tex` 中将 "Edge-IQA with ROI" 的贡献表述从"a novel quality index"调整为"an interpretable, calibratable quality gate integrated into the routing pipeline"
- **验收标准**: Introduction 贡献点不含 "novel algorithm" 类表述
- **需同步文件**: `00_abstract.tex`, `06_conclusion.tex`

### METHOD-M2: Latency Model 非真实网络测量，影响 M1 结论可信度
- **位置**: `05_1_setup.tex` L28
- **证据**: "End-to-end RTT aggregates capture (5ms), edge IQA (N(9,2²)ms), routing (1.5ms), optional edge re-capture resampling (log-normal, p50≈50ms), and cloud upload (uniform 50-550ms)"
- **问题**: M1 RTT 完全基于参数化延迟模型而非真实网络测量。208.3ms vs 374.0ms 的差异来自模型参数的选择而非实际部署数据。虽然 Discussion 中有提及，但 Abstract 的表述容易误导读者以为是真实测量。
- **建议**: (1) Abstract 中明确标注 "under the documented latency model"；(2) 增加 M1 对延迟模型参数的敏感性分析；(3) 强调主要声称是"相对排序"而非绝对延迟值。
- **修改 sketch**:
  ```diff
  - B2 reduces median end-to-end RTT (M1 p50) from 374.0ms to 208.3ms
  + Under the documented latency model, B2 reduces median RTT (M1 p50) from 374.0ms to 208.3ms
  ```
- **验收标准**: Abstract 中包含 "latency model" 或等效限定词
- **需同步文件**: `00_abstract.tex`, `06_conclusion.tex`

### METHOD-M3: 04_1_edge_iqa.tex 内部存在重复段落和矛盾数据
- **位置**: `04_1_edge_iqa.tex` L40-45 vs L50-51
- **证据**: 两个 "Implementation" 段落内容重复；L45 称 p95=9.6ms，L51 称 p95 below 30ms
- **问题**: 同一节内出现两个功能相同的段落，且延迟数据矛盾（9.6ms vs 30ms），严重影响可信度。
- **建议**: 删除 L50-51 段落，保留 L40-45 的更详细版本。
- **修改 sketch**: 删除 `04_1_edge_iqa.tex` L50-51 两行
- **验收标准**: 文件中仅有一处 "Implementation" 段落，p95 数值唯一
- **需同步文件**: 无

## Minor Issues

### METHOD-m2: FSM benchmark 与核心贡献关联弱
- **位置**: `04_2_routing.tex` L71-104
- **问题**: 花了 ~30 行证明"LangGraph 开销可忽略"（0.004%），但这不是审稿人最关心的问题。核心问题是 LangGraph 相比 plain Python 的实际价值（checkpoint、可视化），而非微秒级延迟差异。
- **建议**: 压缩 benchmark 表格为 1-2 句话引用附录，正文聚焦 LangGraph 的架构价值。

### METHOD-m3: ROI padding 策略缺乏消融
- **位置**: `04_1_roi.tex` L6
- **问题**: ROI 使用 8% padding，但未消融不同 padding 比例的影响。
- **建议**: 在 supplementary 中增加 0%/4%/8%/12% padding 对 τ 校准的影响分析。
