## 审稿人 1 (Reviewer 1)
*   **侧重点**：技术合理性与技术缺陷 (Technical soundness / Technical failings)

### 整体评估 (Overall assessment)
该工作在系统工程设计上表现非常完整，巧妙地将耗时且可能包含随机性的图像质量分析与边缘多分支路由策略部署在 FastAPI 网关上，确保其不会影响机器人底层 1 kHz 实时运动控制的安全边界。这为医疗辅助机器人与边缘计算的结合提供了一个清晰的参考架构。然而，本论文的核心技术立论在很大程度上依赖于离线模拟延迟和人工注入的高斯模糊，对于真实临床采集中的动态质量退化（如多角度失焦、局部强反射、反光、运动产生的 rolling shutter 扭曲）和复杂广域网波动的应对能力尚未得到充分证实。

### 谁会对这些结果感兴趣，以及为什么 (Who would be interested in the results, and why)
医疗辅助机器人研发人员、远程医疗系统工程师以及工业边缘控制架构师。他们能够从本文中学习如何合理划分实时机器人控制与非实时 perception 决策的系统边界，并学习如何利用轻量级 FSM 降低感知出错对控制栈的影响。

### 主要优势 (Major strengths)
1.  **架构边界清晰**： percepción 算法和路由决策与硬件控制层显式解耦，避免了深度学习模型（如 B3 中的 MobileNetV3）在机器人低级控制环中引入抖动。
2.  **边缘端高效率**： Edge-IQA 在 CPU 上达到了 p95 < 10 ms 的速度，极大地降低了对于边缘硬件的算力门槛。
3.  **基线对比详尽**： 评估设计涵盖了 B0（直接上传）、B1（只检不重采）、B2（质控加重采）以及引入深度学习的 B3/B4 方案，对比了规则基础与学习基础在 RTT 和有效率上的开销折中。

### 主要顾虑 (Major concerns)
1.  **质量退化建模过于简化**： 论文测试和验证所用的模糊舌象是通过高斯模糊算子（半径 2.5-5.0 px）在清晰原图上合成的。实际机器人采集中的运动模糊往往是方向性的，并且伴随反光、阴影的变化。用合成高斯模糊无法客观评估 Edge-IQA 对真实复杂模糊的敏感度与特异性。
2.  **网络延迟的模拟偏差**： RTT 指标完全由预设的时间数值模型叠加得出（例如 cloud upload 设定为 50--550 ms 的均匀分布）。真实跨国或跨省医疗专网/外网的延迟抖动和丢包机制要复杂得多，模拟测试可能高估了路由算法的鲁棒性。
3.  **物理实验样本量偏小**： 在 Franka 平台上的闭环验证仅执行了 50 次 trials，且没有给出每次重采对图像质量具体提高的定量数据，仅验证了系统执行的重复性趋势。

### 在立论成立前需要解决的技术缺陷 (Technical failings that need to be addressed before the case is established)
1.  **补充真实网络测试**： 必须提供至少一组在真实广域网（如模拟网络损伤仪 WAN Netem 真实丢包或在异地云端真实部署）下的 RTT 吞吐对比，以证明仿真时间模型的预测有效性。
2.  **论证合成模糊的代表性**： 作者需解释为什么合成高斯模糊可以代表机器人在采集过程中的质量缺陷，或者补充使用一小组真实由于手震/运动造成的模糊舌象的测试结果。
3.  **细化物理重采机制**： 正文中提到的 `adaptive_visual_damping`（自适应视觉阻尼）和 `exposure_loop_tuning`（曝光循环调整）在重采时是如何在机器人运动中收敛并影响下一帧的，需给出控制视角的具体参数细节。

### 针对 Nature 风格标准的评估 (Assessment against Nature-style criteria)
*   **原创性 (Originality)**： 中等。图像质量评分（Laplacian 算子）与任务级状态机控制均为成熟技术，但针对舌诊这一高敏感性医疗场景的紧密集成具有应用层面的新意。

*   **技术合理性 (Technical soundness)**： 存在中度缺陷（过于依赖仿真与合成数据）。
*   **非专业读者的可读性 (Readability for nonspecialists)**： 良好，系统框图与逻辑伪代码对非机器人专业读者非常友好。

### 整体评估 (Overall assessment)

1.  **紧扣应用痛点**： 准确指出了中医图像采集中的 GIGO 问题（如 motion blur 图像对下游舌象分类器的破坏性影响）。

## 综合评审结论 (Cross-review synthesis)

*   **共识优势 (Consensus strengths)**：
    1.  **卓越的控制与感知隔离设计**： 将图像质量质控和复杂的网络传输逻辑运行在边缘 FastAPI 接口层，不干涉 1 kHz 机器人底层实时反馈，极大增强了系统的物理安全性。
    2.  **边缘耗时低且硬件友好**： Edge-IQA 专注于 CPU 计算，单帧 p95 低于 10 ms，相比深度非参数图像评估（如 NIQE）或 GPU 深度模型，显现出极佳的现场部署就绪度。
    3.  **完善的流程可审计性**： LangGraph 的每次决策和耗时均会被追溯并记录为结构化 JSONL 日志，符合医疗软件工程的良好实践。
*   **共识技术风险与缺陷 (Consensus technical risks)**：
    1.  **测试场景仿真度低**： 数据集严重依赖合成的高斯模糊，延迟验证完全基于假定延迟模型的数值计算，使得“在真实广域网和真实运动模糊下路由能稳定降低开销”这一结论缺乏实证支撑。
    2.  **主线方案性能过低且效用存疑**： B2 方案的有效率仅为 0.604，相比 B3 深度模型（0.934）差距巨大，且作者优先推崇 B2（仅由于减少了 100 多毫秒的边缘计算耗时）的逻辑，在人命关天的临床诊断场景下显得有些因小失大。
    3.  **验证规模较窄**： 仅有 50 次 Franka 硬件轨迹重复性试验，样本量太小，无法展现统计学置信度。
*   **审稿人侧重点差异 (Where emphasis differs across reviewers)**：
    *   审稿人 1 专注物理合理性：要求补充真实 WAN 测试和真实退化舌象实验，对仿真延迟提出质疑。

## 风险 / 未经证实的主张 (Risk / unsupported claims)

1.  **“闭环机器人控制”表述存在误导风险**： 论文多处使用“Closed-Loop Acquisition”，但图像质控从未接入控制机械臂低层反馈环的输入（如阻尼、速度），而只是在高层任务决策上触发“是否执行重采技能”。为了避免控制理论审稿人的反弹，应将此明确界定为“任务级/决策级闭环（task-level closed-loop routing）”。
2.  **高斯模糊与运动模糊等价性未经证实**： 正文中假设“合成高斯模糊可以代表运动 defocus”，这一假设既没有给出物理成像的理论推导，也没有进行与真实运动模糊图像特征谱的对比，属于未证实的主张。
3.  **“避免低置信度特征进入下游”未经实证**： 论文宣称这一架构可以“避免低置信度特征传导至下游分类器”，但这需要在分类器层面进行对比测试（即：过滤后与未过滤的分类准确率对比），目前这一宣称完全未经实证支持。
4.  **Franka 辅助实验的统计学效力有限**： 仅 50 次 trials 且仅提供 RTT 趋势，样本量严重不足，无法提供强有力的统计置信度。
