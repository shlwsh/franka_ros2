## 1. 云–边–端三层架构

```
┌─────────────────────────────────────────────────────────┐
│  Cloud（云端）                                            │
│  高级视觉模型、EMR 集成（论文 I 中为 stub 占位）              │
│  位置：doctor/paper1                                     │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP（上传清晰帧）
┌──────────────────────────▼──────────────────────────────┐
│  Edge（边侧）                                             │
│  FastAPI 网关 (:8000)                                    │
│  ├── Edge-IQA：给每帧打分 Q_img                           │
│  └── LangGraph：决定 upload / resample / fail_safe       │
│  位置：franka_api_server + doctor/paper1                 │
└──────────────────────────┬──────────────────────────────┘
                           │ DDS / ROS 2
┌──────────────────────────▼──────────────────────────────┐
│  Device（设备层）                                         │
│  FR3 机械臂 + 相机 + MoveIt 运动规划                       │
│  Skills：go_to_tongue_pose / go_to_face_pose             │
│  位置：franka_ros2（franka_hardware, MoveIt）             │
└─────────────────────────────────────────────────────────┘
```

**关键设计原则**：感知和路由**不进** 1 kHz ROS 控制循环，保证实时安全。

## 2. Edge-IQA（边侧图像质量评估）

### 2.1 是什么？

Edge-IQA 是一个**轻量级、可解释、CPU 友好**的图像质量打分器，在边侧网关对每一帧给出 0–1 的质量分数 \(Q_{img}\)。

### 2.2 输入与输出

| 项 | 内容 |
|----|------|
| **输入** | RGB 图像；可选 COCO 舌框 → ROI 裁剪后 resize 512×512 |
| **输出** | `q_img`（0–1 分数）、`flags`（失败标签）、`t_iqa_ms`（耗时） |

> **ShezhenV3 标定（ROI）**：清晰/模糊中位数 **0.516 / 0.414**，τ = **0.465**（n=1144）。

### 2.3 核心公式

设灰度图为 \(I\)，两个特征：

**清晰度 S（Laplacian 方差）**：
\[
S = \mathrm{Var}(\nabla^2 I), \quad \text{归一化到 } [0,1]
\]

**曝光 E（偏好中灰）**：
\[
E = 1 - \frac{|\mathrm{mean}(I) - 0.5|}{0.5}
\]

**融合质量指数**：
\[
Q_{img} = 0.65 \cdot S + 0.35 \cdot E
\]

权重 0.65 / 0.35 表示清晰度比曝光更重要（舌象采集对模糊更敏感）。

### 2.4 失败标签 flags

| 标签 | 触发条件 |
|------|----------|
| `blur` | 清晰度 S < 0.35 |
| `underexposed` | 均值 < 0.25 |
| `overexposed` | 均值 > 0.85 |

### 2.5 阈值 τ 的标定

**ShezhenV3 舌区 ROI（主实验）**：
- 清晰中位数 ≈ **0.516**，模糊 ≈ **0.414**（572 张 val）
- **τ_B2 = 0.465**（`recommended_tau.json`）
- M5 Spearman **ρ ≈ 0.363**（n=1144）

**合成阶段 2（历史对照）**：清晰/模糊 0.819 / 0.191，τ=0.505。

> **τ 的物理含义**：\(Q_{img} \geq \tau\) 认为「足够清晰，可以上传」；\(Q_{img} < \tau\) 认为「需要重拍」。  
> **重要**：真实舌象纹理下 clear/blur cohort **分数区间重叠**（`separation_min_clear_max_blur = −0.541`），故论文**不声称**完美可分，而靠 M2/M1 路由效果 + B3/B4 学习对照 + M5 ρ 共同支撑。

### 2.6 性能指标

| 指标 | 值 |
|------|-----|
| 复杂度 | \(O(HW)\)，线性于像素数 |
| 离线 p50 | 8.01 ms |
| 离线 p95 | 9.57 ms（@512px，CPU） |
| API 路径（含网关+子进程） | ~27 ms（< 35 ms 门槛） |
| 清晰/模糊分离度 | min(clear) − max(blur) = **−0.541**（ROI val，**分数重叠**） |

### 2.7 为什么不用通用深度学习 IQA？

- 边侧需要 **< 30 ms** 实时约束（Edge-IQA p95≈9.6 ms）
- 需要 **可解释** 的 blur/exposure 标签（JSONL 可审计）
- 任务目标是**路由门控**（Q ≥ τ），不是 MOS 排名
- B3 基线为 **ShezhenV3 train 上训练的 MobileNetV3-Small**（val acc **98.3%**）；全量矩阵中 B3@τ_B2 的 M2≈**0.934**，高于 B2 的 **0.604**，但 M1 高约 135 ms；**主 claim 仍基于可解释、低延迟的 B2**

> 详见 [06_Edge-IQA算法详解与业界对比.md](./06_Edge-IQA算法详解与业界对比.md)

## 3. Confidence-Aware Routing（置信度感知路由）

### 3.1 是什么？

给定 Edge-IQA 分数 \(Q_{img}\) 和当前重拍次数 \(r\)，路由函数决定下一步动作。

### 3.2 路由函数（必须背）

\[
\text{route}(s)=
\begin{cases}
\text{upload\_cloud} & Q_{img}\geq\tau \land r\leq K \\
\text{resample\_edge} & Q_{img}<\tau \land r\leq K \\
\text{fail\_safe} & r>K
\end{cases}
\]

| 决策 | 含义 | 后续动作 |
|------|------|----------|
| `upload_cloud` | 质量合格 | 上传到云端 vision stub |
| `resample_edge` | 质量不合格且还有重拍预算 | 调用 `go_to_tongue_pose` 重拍 |
| `fail_safe` | 重拍次数超限 | 上报云侧人工/默认位，终止 |

**超参数**：
- \(\tau = 0.465\)（ShezhenV3 ROI 全量 val）；quick 样本 τ≈0.45
- \(K = 2\)（最大重拍次数）

### 3.5 算法扩展（B2d / B2m / B2u）

详见 [08_算法扩展详解.md](./08_算法扩展详解.md)；quick 数字见 `doctor/paper1/experiments/results/algo_quick_summary.json`。

| 代号 | 公式/机制 | 目的 |
|------|-----------|------|
| **B2d** | \(\tau_t = \tau_0 + \alpha \mathrm{RTT}/\mathrm{RTT}_{ref} + \beta P_{loss}\) | 网络劣化时提高上传门槛 |
| **B2m** | \(Q_t = \lambda Q_{t-1} + (1-\lambda) Q_{img}\)（burst 多帧 EMA） | 降低单帧误判 |
| **B2u** | \(U = w_1 Q - w_2 \mathrm{RTT}/\mathrm{RTT}_{ref} - w_3 C\) | 质量–延迟–代价联合决策 |

**quick 消融（60 帧，seed=0）**：B2 M2=0.60 → B2m/B2u M2=**0.65**；B2m 多帧 IQA 增加 ~69 ms p50。

代码：`langgraph_router/dynamic_tau.py`、`multi_frame_iqa.py`、`utility_route.py`；复现：`bash scripts/paper1_run_algo_quick.sh`。

> **深入阅读**：[08_算法扩展详解.md](./08_算法扩展详解.md)（公式推导、trade-off、答辩速答、复现命令）

### 3.3 LangGraph 状态机

```
capture → edge_iqa → route → upload_cloud
                         → resample_edge → (回到 capture)
                         → fail_safe
```

**与 B1 的关键区别**：B1 只做单次判定，不重拍；B2 重拍后会**重新**进入 `edge_iqa`，形成闭环。

### 3.4 为什么用 LangGraph 而不是普通 FSM？

**答案：路由决策快到框架选择不影响论文 RTT。** 我们在 1\,000 次 trial（5 轮重复）上对六种方案做了实测：

#### 场景 A：纯路由（仅决策函数调用）

| 框架 | 中位 (ms) | P95 (ms) | LOC | 内存 (MB) |
|------|-----------|----------|-----|----------|
| Plain Python | **1.32** | 2.74 | 15 | 34.2 |
| Vanilla FSM | 1.75 | 3.73 | 15 | 35.5 |
| Dataclass FSM | 7.32 | 10.09 | 26 | 37.6 |
| Pydantic FSM | 4.38 | 5.60 | 26 | 37.6 |
| Async FSM | 3.02 | 5.36 | 15 | 37.6 |
| **LangGraph（本文）** | 4.95 | 5.15 | 78 | 46.7 |

**关键数字**：LangGraph 比 Plain Python 慢 3.8×，但绝对差值仅 **3.63 ms / 千次 trial = 3.6 μs/次**。

#### 场景 B：全链路（capture → IQA → route）

| 框架 | 中位 (ms) | 说明 |
|------|-----------|------|
| Plain FSM | 23.4 s | 含图像处理 |
| LangGraph | 38.2 s | 含图像处理 |

LangGraph 额外开销 = 38.2 − 23.4 = **14.8 s / 千次 trial ≈ 15 μs/次**，占 360 ms RTT 的 **0.004%**，完全可忽略。

#### 框架选择论据

| 论据 | Plain Python | LangGraph |
|------|:-----------:|:---------:|
| **路由开销占比** | 基准 | 0.004% RTT，忽略 |
| **断点持久化** | ❌ 不支持 | ✅ 支持中断后恢复 |
| **条件边可视化** | ❌ 需手绘 | ✅ 图定义自动生成 |
| **论文 II 复用** | ❌ 需重学框架 | ✅ 多 Agent 栈直接复用 |
| **JSONL 自动导出** | ❌ 手动 json.dumps | ✅ 框架自动序列化 |

> **必背数字**：LangGraph 路由开销 4.95ms/千次 trial，占 RTT 0.004%，可忽略。选择 LangGraph 的真正理由是**可见性（可视化）、可恢复性（断点）和论文 II 复用**。

> 详见 [07_LangGraph与FSM对比深度分析.md](./07_LangGraph与FSM对比深度分析.md)（含全部原始数据、7 框架对比表、复现命令）。

#### 其他候选框架简评

| 框架 | 为什么不用 |
|------|-----------|
| AutoGen（微软） | 底层用 FSM，适合 Agent 对话，不适合确定性路由 |
| CrewAI | 基于 LangGraph，过度封装，不够透明 |
| Temporal | 需要独立 Server，边缘网关无法离线运行，严重过度设计 |
| LlamaIndex Workflows | 面向 RAG + 知识库，与本文场景无关 |

## 4. 基线 B0–B4 与算法扩展 B2d/B2m/B2u

| 代号 | 描述 | 论文用途 |
|------|------|----------|
| **B0** | 无边缘 IQA；**全部**上传云端再评判 | 主对比（naive baseline） |
| **B1** | 边缘 IQA + 固定 τ；**无** LangGraph（单次判定，不重拍） | 消融「路由/重拍」 |
| **B2** | Edge-IQA + Confidence-Aware Routing + **物理重采** | **本文主方法** |
| **B3 / B3t** | MobileNet @ τ_B2 / τ_B3 | Table III 学习 IQA 对照 |
| **B4** | Hybrid Tier-A/B | Table III |
| **B2d** | B2 + 动态 τ(RTT, P_loss) | 算法创新消融 |
| **B2m** | B2 + 多帧 EMA | 算法创新消融 |
| **B2u** | B2 + 效用函数 U | 算法创新消融 |

### 4.1 如何向导师解释 B2 vs B1？（物理重采版）

> B1 只过滤不重拍，M2 与 B0 同为 **0.560**。B2 物理重采后 M2 **0.604**、M1 p50 **208.3 ms**（3-seed 均值）。  
> **取舍**：M3≈0.44 的重采率换更可审计的有效帧率。

### 4.2 如何向导师解释 B2 vs B0？（全量版）

> B0 全上传：M2=**0.560**，M1 p50=**374 ms**。B2：M2=**0.604**，M1 p50=**208 ms**（约 **44%** RTT 降幅）。  
> **B3/B4** M2≈**0.93** 更高，但含 MobileNet CPU 开销；临床若优先审计与延迟选 B2，若优先有效帧率可选 B4。

### 5.1 RTT 是什么？

**Round-Trip Time（往返时延）**：从采集一帧图像到做出路由决策并完成动作的端到端时间。

主实验 M1 包含**模拟云端往返**；M6 辅轨**不含**云端上传，只测边侧本地回路。

> **陷阱**：M6 的 p50=7.38 ms **不能**与主轨 M1 的 **208 ms（B2）** 或 **374 ms（B0）** 直接对比——测量范围不同。
